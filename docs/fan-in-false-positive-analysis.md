# 집금 룰 오탐 분석 · 2026-11-23

V2 연구 후보에서 **7일·송금 계좌 2개 이상**이라는 집금 조건으로 정상 거래가 많이 포착됐다. 검증 세트의 전체 오탐 123건 중 121건에 집금이 포함됐고, 106건은 집금만 포착됐다. 집금 조건 119개를 비교한 결과, 이전 검증 목표인 보정 Recall 90%를 유지하면서 오탐을 줄인 조합은 없었다.

## 정상 거래에 포착된 특성

| 관찰 | 집금이 포함된 정상 오탐 | 집금이 포함된 세탁 정탐 |
|---|---:|---:|
| 거래 수 | 121 | 93 |
| 7일간 서로 다른 송금 계좌가 2개 | 67/121 | 43/93 |
| 7일간 서로 다른 송금 계좌가 2~3개 | 106/121 | 62/93 |
| 최근 24시간으로 줄이면 송금 계좌가 2개 미만 | 76/121 | 32/93 |
| 첫 입금부터 대상 거래까지의 중앙 경과 시간 | 약 6.18일 | 약 5.76일 |
| 근거 입금 건수 중앙값 | 17 | 15 |
| 조회 상한으로 일부 관계가 생략된 그래프 | 89/121 | 75/93 |

정상 오탐 121건의 수취 계좌는 모두 달랐다. 몇 개 수취 계좌에 집중된 문제보다 7일 동안 서로 다른 두 계좌의 입금을 집금으로 보는 조건이 폭넓게 적용된 결과로 볼 수 있다. 집금에 걸린 정상과 세탁 거래 모두 2~3개의 송금 계좌에 많이 분포했다. 두 집단 모두 집금 근거 거래의 수취 통화가 사례 안에서 동일했으므로, 같은 수취 통화 조건은 이번 표본을 가르지 못했다. 이 표는 합성 데이터의 라벨과 조회 그래프의 관찰을 기준으로 한다. 거래 목적이나 수취 계좌의 전체 이력은 확인 범위 밖이다.

## 조건별 검증 결과

시점은 대상 거래 시각까지로 두고 집금 시간창(1시간~7일), 최소 송금 계좌 수(2~12개), 후보 계좌 집계 방식 세 가지를 비교했다. 분산과 순환의 결과는 그대로 두고 집금의 경고 여부만 바꿔 전체 알림을 다시 계산했다. 아래 정탐·오탐 건수는 검증 250건의 관측값이며, Recall은 V2 표본 가중치로 보정했다. 정상 표본은 같은 가중치를 쓰므로 오탐률은 오탐 건수를 정상 150건으로 나눈 값과 같다.

| 집금 조건 | 탐지한 세탁 거래 / 100 | 오탐 / 150 | 보정 Recall | 오탐률 |
|---|---:|---:|---:|---:|
| V2 후보 · 7일 / 2계좌 | 94 | 123 | 93.74% | 82.00% |
| 7일 / 3계좌 | 60 | 65 | 59.66% | 43.33% |
| 3일 / 2계좌 | 78 | 70 | 77.56% | 46.67% |
| 24시간 / 2계좌 | 73 | 57 | 72.58% | 38.00% |
| 12시간 / 2계좌 | 55 | 39 | 54.34% | 26.00% |
| 3일 / 앞선 이력에 보이지 않던 송금 계좌 2개 | 49 | 22 | 48.18% | 14.67% |

마지막 조건의 이전 이력은 7일 조회 그래프 중 최근 3일 앞의 구간이다. 대상 거래의 송금 계좌도 그 구간에 보이지 않아야 한다. 조회 상한으로 일부 이력이 빠질 수 있으므로 실제 신규 송금 계좌 여부로 해석하지 않는다. 세탁 정탐 집계는 모든 정답 유형을 포함한다. 집금 정답 유형만 보면 6건이며, 24시간 조건에서는 전체 룰을 합쳐 5건을 포착했다. 작은 유형별 표본은 조건 선택을 뒷받침하는 참고 수치다.

24시간 조건은 정상 오탐 66건을 줄이는 대신 세탁 정탐 21건을 놓쳤다. 기준 변경보다 **수취 계좌의 평소 입금 활동 대비 최근 증가**를 다음 비교 대상으로 잡는다. 예를 들어 평소 같은 시간대의 송금 계좌 수와 최근 수치를 비교하는 특성을 만들어, 처음 보는 평가 표본에서 룰 단독과 룰·ML 결합의 Recall·오탐률·알림 건수를 함께 평가한다.

## 재현

기존 [V2 평가 입력](evaluation-v2.md)과 동결된 룰 파일로 아래 명령을 실행한다. 검증 파일 250건만 읽으며, 최종평가 파일은 읽지 않는다. 해시와 기존 검증 결과를 대조하고, 7일·2계좌 조건이 당시 알림과 일치함을 확인한다. 실행 JSON은 집계와 비교 조건을 담고 Git 제외 폴더에 저장한다.

```powershell
python scripts/analyze-fan-in-false-positives.py --output artifacts/fan-in-false-positives-new-run.json
```

실제 결과 파일은 `artifacts/fan-in-false-positives-20261123.json`이다. [기존 V2 최종평가 결과](db-rule-v2.md)와 [500건 Neo4j 조회 대조](neo4j-evaluation-replay.md)는 다른 범위의 기록이다.


[후속 실험](recipient-activity-evaluation.md)에서 수취 계좌별 평소 입금과 최근 입금을 비교했다. 새 평가 표본의 성능과 이력 확보율을 확인할 수 있다.
