# TraceOn 시연과 평가 결과 · 2026-11-26

## 공통 시연 순서

1. `TX-000619283`을 열어 7일·2홉에서 69건을 확인한다. 연결 계좌와 순환 근거를 강조하고 룰 점수와 고정 룰+ML 점수를 표시한다.
2. 추가 조회 가능한 계좌를 선택해 72건으로 확장한다. 신규 3건과 중복 1건을 확인한다. 이전 그래프에 묶인 초안과 판정은 화면에서 초기화한다.
3. 새 검토 초안을 열어 거래 사실과 인용 원문을 확인한다. 먼저 수치·인용 코드 검증을 실행하고 보고서 Judge에 넘긴다.
4. 그래프·초안·Judge를 저장하고 이력에서 다시 연다. 화면은 저장 당시 상태를 표시한다. 최종 확인은 사람이 한다.

시연 자료는 CSV 1,902거래와 RAG 문서 10개·청크 61개를 사용한다. [공통 시연 확인표](team-integration-check.md)의 해시 기준으로 대조한다. Spring은 같은 주소에서 UI와 API를 제공하고 RAG는 Compose 내부에서 호출한다. 그래프별 사전 계산 점수는 `demo-scores.json`의 대상·시점·그래프 SHA-256이 모두 일치할 때 표시한다. 문서·점수 파일·자격증명은 Git 외부에서 관리한다.

## 검증 범위

- 격리된 Compose에서 1,902건을 적재하고 69→72건, 확장 재전송, 이전 초안 요청 4종 차단, 거래 사실 2개, 인용 14개, 저장 및 복원을 확인했다.
- RAG 이미지에는 같은 팀 룰 모듈을 포함한다. 보고서 Judge에는 내부 서비스 호스트를 명시하고, Spring·룰·RAG 간 호출 규격은 유지했다.
- Spring 46개, RAG 276개, 프론트 49개가 통과했다. 실제 모델 연결 전의 화면 확인에서는 모델 미설정 결과인 `not_judged`를 표시하고 저장한다.
- 실제 Edge 브라우저에서 같은 거래의 69→72건, 그래프별 결합 점수, 확장 시 이전 Judge 초기화, 저장 당시 Judge 복원까지 확인했다.
