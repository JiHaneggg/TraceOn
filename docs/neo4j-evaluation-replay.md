# Neo4j V2 평가 조회 대조 · 2026-11-23

기존 V2 평가의 검증 250건과 최종평가 250건을 별도의 Neo4j 5.26.32에서 다시 조회했다. 두 평가 구간 모두 기존 그래프와 **250/250건 일치**했다.

| 검사 | 검증 구간 | 최종평가 구간 |
|---|---:|---:|
| 그래프와 거래 ID·금액 문자열·통화·계좌·시각 일치 | 250/250 | 250/250 |
| 조회 상한으로 생략된 그래프 수 | 양쪽 188 | 양쪽 172 |
| 기존 룰의 점수·분류·판단 근거 일치 | 250/250 | 250/250 |
| 고정된 개선 후보의 점수·분류·판단 근거 일치 | 250/250 | 250/250 |

조회 조건은 대상 시점까지의 7일, 2홉, 계좌당 최근 50건, 합계 최대 1,000거래다. 전체 5,078,345거래를 인덱싱한 기존 SQLite에서 대상 거래와 이 조건의 계좌 조회에 필요한 행을 모았다. 계좌당 51번째 행까지 포함해 생략 여부를 재현했다. 중복을 합쳐 계좌 21,757개와 거래 131,089건을 평가 전용 Neo4j에 넣었다. 기존 Cypher의 대상 조회 500개와 서로 다른 계좌·시간창 조회 6,491개를 실행했다. 계좌 조회 결과의 ID와 순서도 6,491/6,491개 모두 일치했다.

비교는 원천 인덱스·기존 평가 파일·고정 룰의 해시 확인으로 시작한다. 그래프에서 자료 범위를 나타내는 두 필드와 룰 응답의 원장 완전성 표시만 비교 대상에서 제외했다. 그래프의 생략 상태는 비교에 포함했다. 이 결과가 다루는 범위는 **기존 500건의 고정된 조회**다. [기존 V2 성능 지표](db-rule-v2.md)는 그대로 보존했다. 운영 DB의 전체 거래 적재, 대규모 성능, 새 탐지 성능에는 별도 검증이 필요하다.

룰 개선 후보의 다음 검토는 집금부터 시작한다. 기존 검증 구간의 정상 150건에서 후보 오탐은 123건이었다. 이 중 121건에 집금 룰이 포함됐고, 106건은 집금만 해당했다. 거래 빈도나 반복 상대 계좌 등 추가 특성을 검증 구간에서 조사할 근거다. 이 진단에서는 룰과 점수 기준을 변경하지 않았다.

## 재현

저장소의 [V2 평가 입력](evaluation-v2.md)과 고정 설정 파일, 로컬 Neo4j 5.26.32·JDK 21을 준비한 뒤 PowerShell 7에서 실행한다.

```powershell
./scripts/verify-neo4j-evaluation.ps1 -RunName v2-replay-01
```

평가 전용 저장소는 `artifacts/neo4j-evaluation/<RunName>/`에 생성하며 실행마다 새 이름을 사용한다. 기본 평가 포트는 17474다. 스크립트가 새 프로세스를 띄우고 완료 후 종료한다. 시연 DB는 별도다. `comparison.json`에 건수·불일치·해시를 남긴다. DB 파일·CSV·로그·결과 JSON은 `artifacts/`로 Git에서 제외한다.
