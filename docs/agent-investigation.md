# 에이전트 조사 계층 · PPT 구조 구현 기록 · 2026-11-25

에이전트 담당 작업 기록이다. 사전발표 PPT의 조사 흐름을 `agent-service/`에 LangGraph로 구현하고 있다. 실행 방법과 노드별 상세는 [agent-service/README.md](../agent-service/README.md)에 있다. 이 문서는 배경, 결정 사항, 검증 결과, 팀과 논의할 항목을 기록한다. 아래 수치는 모두 개발·검증 구간 결과이며 최종 벤치마크가 아니다.

## 1. 배경: 기존 에이전트와 PPT 설계의 차이

공유 브랜치 `codex/rag-safe-share`의 `rag-service/agent_workflow.py`(`run_review_workflow`)를 점검했다.

- 처리 순서가 코드에 고정된 파이프라인이다: 근거 맥락 → 사실·인용 수집 → 초안 → 코드 검증 → 선택적 Judge.
- 초안의 LLM(`reports.openai_plan`)은 관찰·인용·검토 항목 ID의 순서만 고른다. 문장은 템플릿이다. 실제 호출에서도 템플릿과 순서만 달랐다.
- Judge(단일·토론)는 초안의 의미를 검증한다. 거래를 탐지하는 방식이 아니다.
- `agent_tools.json`의 도구 10개는 근거·보고서 도구이고 모델에 전달되지 않는다.

사전발표 PPT(Slide 6·8·9)와 `멘토링_준비_및_파이프라인_정리` 3-3절의 설계와 비교하면 다음이 없었다.

| PPT 설계 | 기존 코드 |
|---|---|
| `basic_profile`(프로파일·임베딩 유사도), 2×2 게이트, 종료 조건 4단계 | 없음 |
| `investigator`: LLM이 그래프 도구를 골라 multi-hop 추적 | 없음 (백엔드 고정 조회 7일·2홉) |
| `typology`: LLM이 규정 RAG·체크리스트로 유형 판별 | 없음 (룰 3종이 유형 결정) |
| `str_writer`: 사실·해석 분리 초안 | 템플릿 초안, 해석 없음 |
| `verifier` | 있음 (사실·인용·원문·렌더링 검증, 계획보다 강함) |
| 알림당 LLM 8회·비용 추적, `human_review` 승인·반려 | 없음 |
| 비교군 B2(단일 LLM 1회 판정) | 없음 |

그래서 PPT 구조를 새 폴더에 구현하기로 했다. 기존 도구·검증·룰·ML 코드는 수정하지 않고 재사용한다.

## 3. 데이터 준비와 팀 산출물 재현

- Kaggle `ealtman2019/ibm-transactions-for-anti-money-laundering-aml`에서 HI-Small 파일 3개만 받았다(487MB, 크기 일치).
- 전처리 결과가 팀 기록과 같다: 거래 5,078,345, 세탁 5,177, 자기 거래 591,212, 패턴 거래 3,209, 계좌 515,088. `data-model.md`의 515,080은 계좌번호만 센 값이고, (은행, 계좌번호)로 세면 515,088이다.
- 시범 12건, V2 평가 500건, 원본 색인(1.4GB)을 Neo4j 없이 팀 스크립트로 만들었다. V2 룰 설정, 입금 활동 평가 4개 행, 룰+ML 결합 5개 행이 팀 기록과 모두 같았다.
- 팀 스크립트가 요구하는 Neo4j 시범 결과 대신 같은 시범 12건의 오프라인 평가를 기준선으로 썼다. 기준선은 비교 기록에만 쓰이며 결과는 같았다.

## 5. 기존 rag-service 에이전트 점검 결과 (코드 수정 없음)

거래 3건짜리 합성 사례로 `gpt-6-luna`를 10회 호출했다. 총비용은 $0.0064였다.

| 확인 | 결과 |
|---|---|
| LLM 초안 + 단일 Judge (2회) | 모두 통과. 1회 약 $0.0011, 10~12초 |
| LLM 초안 + 토론 Judge | 1회차는 2라운드 응답이 무효라 보류, 재실행은 통과. 약 $0.0021, 15~19초 |
| 근거 없는 질문 | 모델 호출 없이 보류 |

오프라인 모의 전송으로 재현한 문제:

- 초안 생성 중 연결 끊김(`RemoteDisconnected`, `IncompleteRead`)과 Judge 응답 잘림(`IncompleteRead`)은 결과 없이 예외로 끝난다. 실행 기록도 남지 않는다.
- API 키가 없어도 초안 생성을 3회 시도한다. 반대로 일시적인 네트워크 오류는 재시도 전에 끝난다.
- Judge 항목 하나에 근거 ID가 빠지면 판정 전체가 점수 없이 보류된다(MG-04와 같은 원인). Judge에는 재시도가 없다.
- 토론 Judge는 2라운드에 1라운드 판정을 넘기면서 독립 판단을 요구한다. 실패 원인은 `rounds` 안에만 남는다.
- 보류 상태가 근거 부족과 모델 실패를 구분하지 않는다. 토큰 사용량과 Judge 응답 ID를 기록하지 않는다.
- `run_review_workflow`는 RAG 서버·Spring·프론트에서 호출되지 않는다.
- 초안 검증 평가의 F1 1.0은 같은 계획으로 다시 그려 비교하는 구조라 주입한 결함만 잡는다. 다중 그래프 Judge 평가는 개발자가 확정한 라벨을 `human_reviewed`로 기록한다.

새 코드(4단계 공통 LLM 호출부)에는 오류 분류, 제한된 재시도와 백오프, 예외 없는 보류 반환, 시간 상한, 비용 기록을 반영한다. 기존 코드 수정은 팀장과 협의한다.

## 6. 팀과 논의할 항목

1. 백엔드 알림 기본값을 V2 룰로 바꿀지. 팀 문서는 API 기본값을 자동으로 바꾸지 않는다고 정했다.
2. 알림 기준 모두가 놓친 세탁 6건(BIPARTITE, CYCLE, 유형 미지정). 현재 룰은 집금·분산·순환 3종이다.
3. 룰+ML을 ml-service로 제공할지. 지금은 에이전트가 로컬 원본 색인으로 수취 계좌 이력을 읽는다.
4. 최종 벤치마크 표본. ML 학습에 쓴 V2 검증 250건은 제외해야 한다.
5. 발표 표현. PPT의 GDS 노드 임베딩은 같은 알고리즘(FastRP)을 Python으로 구현했고 신호가 없어 게이트에서 룰+ML 점수로 바꿨다.
6. 기존 rag-service 에이전트의 견고성 문제(5절).

## 7. 공통 LLM 호출부와 실패 구분 (4단계)

5절의 문제를 새 코드에 반영했다(`agent-service/llm_client.py`). 모든 LLM 노드가 같은 호출부를 쓴다.

- 오류를 설정·인증·잔액·요청 / 일시 오류 / 출력 형식 / 거절 / 예산·마감으로 나눈다. 일시 오류만 최대 2회 재시도(지수 백오프, `Retry-After` 반영)하고, 출력 형식 오류는 1회 재시도한다. 나머지는 재시도하지 않는다.
- 연결 끊김과 응답 잘림을 포함해 어떤 오류도 예외로 끝나지 않는다. 결과에는 키와 제공자 오류 원문을 남기지 않는다.
- 실패한 시도까지 호출 수·토큰·비용에 포함하고, 알림당 LLM 8회와 60초를 넘지 않는다.
- 사람 검토로 보낼 때 `hold.category`를 `evidence_insufficient`(근거 부족), `model_failure`(모델 실패), `budget_exceeded`(예산 초과), `no_progress`(진전 없음) 중 하나로 남긴다. 검증에서 틀린 초안은 보류가 아닌 반려로 구분한다. 백엔드가 요청한 Judge 응답의 실패 구분은 이 분류를 따른다.
- 실제 API 점검(2026-11-25): 구조화 응답 정상(토큰 234, $0.000055, 3.5초), 없는 모델은 재시도 없이 `llm_model_not_found`. 오류 분류별 동작은 모의 전송 테스트 18개로 확인했다.

## 8. 다음 단계

5 `investigator`(그래프 도구 선택 루프) → 6 `typology` → 7 `str_writer` → 8 `verifier`(기존 검증·Judge 재사용) → 9 `human_review` → 10 평가(B1 룰 단독 / B2 LLM 1회 / 전체 시스템, 오탐 감소율·Recall 손실·유형 정확도·비용).

## 2026-11-26 통합 작업

잘린 그래프에서 근거가 부족하면 게이트가 자동 종료를 보류하고 사람 검토로 넘긴다. 조사 모델은 고정 그래프에 대해 시간·통과·금액·룰 근거 중 필요한 조회를 고르고, 제공된 사실 ID만 반환한다. 유형 판별에는 RAG 청크 ID를 요구한다. 검토 초안은 기존 RAG 템플릿으로 만들고, 사실·인용 검증을 통과한 경우 기존 Judge 검증 규격과 공통 LLM 호출부를 사용한다. 마지막 상태에는 사람 검토가 필요하다고 기록한다.

독립 239건의 오프라인 비교에서 7일 V2 룰과 게이트가 동일한 이상 73건을 적중하고 16건을 놓쳤다. 게이트 적용 후 정상 후보가 109건에서 105건으로 줄었다. 게이트 평가는 OpenAI 호출 없이 완료했다. 전체 조사의 모델 호출 수·비용과 유형 판별 정확도는 실호출 및 골든 사례 평가에서 측정한다.

에이전트 자동 테스트 84개를 통과했다. 실제 Compose 그래프와 RAG 색인에 모의 제공자를 연결한 검사에서 허용 조회 선택, 유형 가설, 코드 검증, 보고서 Judge 및 사람 검토 전달을 확인했다.

`agent-service/evaluate_investigation.py`는 평가 표본과 동결 모델·원본 색인·학습 ID를 읽는다. 기본 `--mode gate`는 오프라인 평가다. `--mode openai`는 같은 고정 표본의 조사·초안·Judge를 실행한다. 실행하는 셸에서 OpenAI 환경변수를 설정하고 `--corpus`에 RAG 색인을 지정한다. `--help`의 경로 인자는 팀의 로컬 자료를 사용한다. 부분 결과는 같은 모드·모델·출력 파일명으로 재개할 수 있다.

### 실제 모델을 사용한 개발 파일럿

첫 실행에서 순환 시연 그래프에는 집금과 순환이 함께 있었고, 모델은 집금을 주 유형으로 선택했다. 유형 판별이 실제 관찰과 연결되도록 같은 유형의 직접 근거 ID를 요구했다. 대상 거래에서 시간 순서에 따른 닫힌 순환이 확인되면 주 유형으로 먼저 검토하고, 자료가 충분하지 않으면 보류할 수 있다. 이 기준은 독립 표본 실행 전에 개발 자료에서 적용했다.

| 개발 사례 | 실제 결과 | 기록된 모델 호출 |
| --- | --- | ---: |
| 공통 순환 시연 거래 | 순환 유형, 수치·인용 검증과 Judge 통과, 사람 검토로 전달 | 2 |
| 정상 라벨 검토 후보 | 조사 도구 선택, 집금 관찰, 수치·인용 검증과 Judge 통과, 사람 검토로 전달 | 4 |
| 그래프가 잘려 근거 부족 | 자동 종료 없이 보류, 사람 검토로 전달 | 0 |

재실행 3건의 기록 비용은 0.003682달러다. 첫 실행 5회와 재실행 6회를 합쳐 모델 요청을 총 11회 기록했다. 집금은 그래프에서 관찰한 거래 구조를 뜻한다. 정상 표본의 보고서 검증 통과는 사람 검토가 필요한 거래 관찰을 문서로 뒷받침했다는 결과다.
