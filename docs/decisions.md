# 설계 결정 기록 (ADR)

결정이 바뀌면 기존 항목을 지우지 않고 새 항목을 추가합니다.

## ADR-001. Neo4j 접근과 Subgraph 추출은 백엔드가 단독으로 담당한다 (2026-10-30)

- 배경: Subgraph 추출 로직이 여러 언어·서비스에 중복되면, Rule / LLM / Hybrid가 서로 다른 입력으로 평가되어 비교 실험이 무효가 된다.
- 결정: Spring Boot 백엔드만 Neo4j에 접근한다. Rule·ML·LLM 서비스는 백엔드가 전달한 Subgraph JSON만 사용한다.
- 영향: 각 서비스는 Neo4j 드라이버가 필요 없다. 백엔드에 Subgraph 조회 API를 제공해야 한다.

## ADR-002. 팀 프로토타입(aml-prototype)은 코드를 재사용하지 않는다 (2026-10-30)

- 결정: 다른 팀원의 Python 프로토타입은 Docker 구성(Neo4j 이미지 버전, 포트, 헬스체크 등)만 참고하고, 코드는 처음부터 새로 구현한다.

## ADR-003. 기본 기술 및 저장소 구성 (2026-10-30)

- 모노레포: backend, ml-service, docs를 한 저장소에서 관리한다.
- Spring Boot 4.x + Java 21 + Gradle. (3.5는 2026-06 OSS 지원 종료)
- docker-compose.yml은 저장소 루트에 둔다. (하위 폴더에 두면 빌드 경로가 복잡해짐)
- Neo4j는 핵심 구성요소이므로 compose profile 없이 항상 실행한다.
- 브랜치: main / develop / feature/*.

## ADR-004. Rule Engine은 별도 서비스로 구현한다고 가정한다 (2026-10-30, 가정)

- 결정: Rule Engine은 Rule 담당자가 별도 서비스로 구현한다. 백엔드는 `RuleDetectionClient`가 HTTP로 호출한다.
- 영향: Rule / ML 클라이언트가 같은 형태(Subgraph JSON 요청 → 점수 + 근거 응답)가 되므로 공통 규격으로 설계한다.
- 확정 필요: Rule 담당자와 구현 언어·포트·API 규격 합의.

## ADR-005. 백엔드 기본 설정 (2026-10-30)

- 패키지: `com.traceon`
- Java 21을 Gradle toolchain으로 고정한다. 개발 PC에 JDK 25만 있어도 Gradle이 JDK 21을 자동으로 내려받아 빌드한다 (foojay resolver).
- 이유: 팀원마다 설치된 JDK가 달라도 같은 버전으로 컴파일·테스트되도록 하기 위함.

## ADR-006. 데이터셋과 그래프 모델: 거래 = 관계, 탐지·평가 단위 = 거래 (2026-10-31)

- 데이터셋: IBM Transactions for Anti-Money Laundering (AML), 합성 데이터. 사용할 규모(HI/LI, Small/Medium/Large)는 확정 필요.
- 결정: `(:Account)-[:TRANSFER]->(:Account)`. 거래 1건 = TRANSFER 관계 1개. 정답 라벨 `isLaundering`은 관계 속성.
- 이유
  1. 정답 라벨이 거래 단위(`Is Laundering`)이므로 탐지·평가 단위는 거래다. 라벨·점수는 관계 속성으로 충분히 저장된다.
  2. 데이터셋의 패턴 정의("Max 12 hops", "9-degree Fan-In")가 계좌→계좌 hop 기준이라 Hop 의미가 일치한다.
  3. IBM AML의 대표 ML 접근(GNN 엣지 분류)과 그래프 구조가 같아 ML 담당자가 그대로 내보내 쓸 수 있다.
  4. 거래를 노드로 만들면 노드 수와 hop 수가 2배가 되고, 거래에 연결할 다른 개체(기기·IP 등)가 데이터셋에 없다.
- 보완: 데이터셋에 거래 ID가 없으므로 전처리에서 결정적 `txId`를 부여하고, 모든 담당자가 같은 ID를 사용한다.

## ADR-007. 전처리는 백엔드 담당이 Python으로 구현하고, 결과를 팀 공통 데이터로 배포한다 (2026-10-31)

- 위치: `data-pipeline/`
- 이유: txId·계좌 식별자·환율이 담당자마다 다르면 Rule / ML / LLM / Hybrid 결과를 거래 단위로 비교할 수 없다.
- 구현: 표준 라이브러리만 사용하는 스트리밍 처리. 별도 패키지 설치가 필요 없고, 500만 행도 적은 메모리로 처리한다.
- 산출물: `data/processed/{데이터셋}/` 아래 공통 CSV와 manifest.json(입력 파일 해시, 행 수, 환율). 대용량이므로 Git에 올리지 않는다.

## ADR-008. Neo4j 적재는 neo4j-admin database import로 한다 (2026-10-31)

- 이유: 실험용 고정 데이터라 매번 빈 DB에 새로 적재해도 문제없고, 500만 관계를 가장 빠르고 재현성 있게 넣을 수 있다.
- 방식: `data/processed` → `neo4j_export.py` → `data/import` → 컨테이너 안에서 import → `schema.cypher`로 제약조건·인덱스 생성.
- 제약: 적재 중 DB 중지 필요, 기존 데이터 덮어씀. 증분 추가가 필요해지면 LOAD CSV 방식을 추가 검토한다.

## ADR-009. DB·룰 MVP와 평가 범위 (2026-11-14)

- 룰 점수와 ML 점수를 결합하고 LLM이 근거를 설명하는 방향을 유지한다.
- 초기 시연은 CYCLE/FAN-IN 대표 사례와 정상 대조군을 담은 작은 서브그래프에서 검증한다. 표본 지표는 전체 성능으로 주장하지 않는다.
- 기본 조회는 대상 시점 이전 7일, 2홉, 계좌별 최근 50거래, 최대 1,000거래다. 미래 거래는 포함하지 않는다. 잘린 범위를 명시한다.
- 원본 금액 문자열을 보존하고 Decimal로 통화별 집계한다. 정답 속성은 공통 탐지 입력에서 제거한다.
- 룰 엔진은 DB에 접근하지 않는 Python 모듈과 로컬 HTTP 연동점으로 제공한다. 운영 DB 조회는 ADR-001대로 Spring에서 담당한다.
- 기존 대량 import는 유지한다. MVP 검증용 소량 적재는 별도 관리자 도구로 추가하며, 다른 데이터셋/버전이 있는 DB에는 적재하지 않는다.

## ADR-010. 룰 V2의 시간순 평가와 후보 설정 (2026-11-14)

- 과거 1차 결과를 보존하고 새 검증 250건·최종평가 250건을 분리한다. 이전 노출 대상과 패턴 가족을 제외하고, 최종평가 패턴은 경계 시각 이후 시작한 가족만 사용한다.
- 유형별 층화와 정상/세탁 분리 추출을 사용하므로 표본 지표와 모집단 비율을 보정한 지표를 함께 보고한다.
- 집금·분산 증거 기준을 별도로 설정한다. 검증에서는 룰 점수 65를 막지 않도록 전체 점수 기준을 65로 고정한다. 216개 조합은 최종평가 전에 정한다.
- 검증으로 선택한 설정과 규칙 코드·데이터 해시를 고정한 뒤 최종평가를 한 번 수행한다. 고정 이후 내용이 바뀌거나 기존 결과를 덮어쓰려 하면 중단한다.
- 원천 전체의 디스크 인덱스는 오프라인 평가 준비용이다. 운영 Neo4j와 Spring의 책임 분리는 유지한다.
- 후보는 연구용이며 API 기본값을 자동 변경하지 않는다. 상세 결과는 `docs/db-rule-v2.md`에 기록한다.

## ADR-011. RAG는 거래 사실과 공식 안내 자료의 근거를 묶어 에이전트에 제공한다 (2026-11-14)

- 현재 사용자 역할은 팀장·RAG 담당이다. 앞선 DB·룰 산출물은 유지하고 협업의 입력으로 사용한다.
- RAG 서비스는 Spring의 공통 Graph JSON과 룰 결과를 받는다. DB 자격증명·임의 Cypher·오프라인 평가 DB에 접근하지 않는다. 관리자 통합 검증 스크립트만 기존 Neo4j 도구를 사용한다.
- 초기 코퍼스는 KoFIU 공식 STR·CTR·CDD 안내의 선별 절 3문서다. HTML 원본 스냅샷, SHA256, 수집 시각, 정규화 본문의 문자 위치를 기록한다. 안내를 법령 원문이나 특정 시행일의 법적 판정으로 표시하지 않는다.
- BM25와 한국어 문자 2-gram을 기준선으로 사용한다. 임베딩·벡터 DB·유료 API 없이 검색 흐름을 먼저 연결한다. 의미 검색·유형별 사례·시행일 필터는 후속 개선이다.
- 거래 금액은 문자열과 Decimal로 계산하고 통화·지급/수취를 분리한다. 룰 결과를 기존 엔진으로 재검산해 근거 변조를 거부한다. 룰 설정·기존 평가 결과를 변경하지 않는다.
- 구조화 사실 ID와 원문 인용을 검증한다. 자유 문장의 의미, 법률 적용, 최종 STR 제출은 자동 확정하지 않는다. 검색 점수나 구조화 검사 통과를 환각 0%로 주장하지 않는다.
- 문서와 거래 속성은 신뢰할 수 없는 데이터다. Agent는 허용된 도구만 호출하며 텍스트에 포함된 지시를 실행하지 않는다.

## ADR-012. RAG V2의 출처 범위와 제어된 검토 초안 (2026-11-14)

- 공식 해외 징후 자료 FinCEN·FINTRAC을 foreign_typology로 분리하고 US/CA 관할·발행/수정 시각·원본 해시를 보존한다. 한국 법령·내규로 적용하지 않는다.
- 법령 원문은 시스템 점검으로 미확보, FATF PDF는 403으로 수집 실패했다. 이를 색인에서 제외하고 pending_sources.json에 남긴다. 법령/시행일·은행 내부 규정·점수에 따른 보고 기준은 필요한 출처가 없으면 insufficient_scope로 보류한다. 이 규칙을 일반 의미 검증으로 주장하지 않는다.
- 검토 초안은 검산된 사실·사전에 정의한 설명·인용으로 렌더링한다. 기본 template 모드는 LLM을 호출하지 않는다. 명시적 openai 모드는 설정된 모델이 제공한 ID만 선택·정렬하도록 Structured Outputs를 사용한다.
- 모델의 API 거절·미완료·잘못된 ID·필수 근거 누락은 보고서 생성 실패다. 미설정/실패 시 template으로 조용히 전환하지 않는다. 모든 초안은 사람 검토 대기 상태다.
- 실제 LLM 검증은 키·모델 설정이 없어 아직 하지 않았다. 모의 전송 테스트와 실제 Neo4j template 보고서 검사를 구분한다. 기존 룰 평가와 1차 RAG 산출물은 보존한다.

## ADR-013. 검색 대표 결과의 중복 제거와 원본 보조 인용 (2026-11-14)

- 같은 문서·원본 버전·관할·종류·절의 최고 점수 청크를 대표 결과로 선택한다. 서로 다른 절·출처·버전은 합치지 않는다.
- 각 대표 결과의 적격 보조 청크를 최대 2개 전달한다. 원본 ID·본문·해시·문자 위치를 보존하고 Context 인용에서 primary/supporting을 구분한다. 본문을 합쳐 새 인용처럼 표시하지 않는다.
- 질문 불용어·영어 단복수·제한된 한국어/영어 검색어 대응을 처리한다. 확보하지 않은 고객정보·금리·내규 등 일부 요청은 자료 부족으로 보류한다. 이 처리로 의미 검증이나 법적 판정이 가능하다고 주장하지 않는다.
- 기존 V2 코드와 48개 새 질문으로 비교한다. 개발을 반복했으므로 전체를 개발·회귀 질문으로 취급하고 독립 최종평가로 부르지 않는다. 최초·중간·최종 결과와 코드·질문·코퍼스 해시를 보존한다.
- 대표 top3의 절 Recall과, 문맥 예산이 늘어난 보조 본문 포함 근거 확보율을 별도 지표로 보고한다. 누락·모호한 정답 판단을 숨기거나 사후 정답 수정으로 지표를 높이지 않는다.

## ADR-014. 버전 고정 근거 조회와 전체 보고서 검사 (2026-11-14)

- 인용 ID+corpusSha256로 원문 URL·절·본문·강조 위치를 조회한다. 저장된 원본 해시·정규화 텍스트·청크 위치를 대조하고 과거 버전이 없으면 409로 거부한다. 임의 파일 경로나 라이브 URL을 읽지 않는다.
- 사실 조회는 같은 백엔드 Graph·Rule·Query로 값을 재계산해 근거 거래와 반환한다. RAG는 DB 자격증명을 받지 않고 상위 원장의 진위를 인증하지 않는다.
- 보고서 준비/검사 API는 금액·시각·경과 초·건수·전체 사실 포함·원문 인용·스냅샷·제어된 JSON/Markdown을 검사한다. 자기 해시를 다시 계산한 변조도 원래 근거와 비교해 거부한다.
- index_only는 원문 검증 성공으로 표시하지 않는다. 최종 제출 가능이나 법률/의미 판정을 자동 확정하지 않는다. 항상 사람 검토를 요구한다.
- 정의·비교 질의에는 이미 적격인 관련 개념 절을 우선 확보한다. 원래 정답표와 과거 결과는 유지하고 이미 노출된 48개 질문의 개선을 최종 일반화 성능으로 주장하지 않는다.

## ADR-015. 문서 후보 등록과 검색 반영을 분리한다 (2026-11-15)

- 로컬 관리자 명령으로 문서 메타데이터·선별 절·원본을 등록한다. 신규/수정 후보는 명시적으로 반영할 때까지 검색에 사용하지 않는다. 같은 원본과 같은 메타데이터는 등록 시각이 달라도 기존 버전을 재사용한다.
- 원본 바이트·정규화 전체 본문·메타데이터 변경을 구분하고 선택 절의 차이를 미리 보여준다. 알 수 없는 시행일은 null로 유지하고 수집/등록일과 구분한다. 메타데이터나 해시를 출처 진위·법적 적용 인증으로 해석하지 않는다.
- 반영은 현재 색인 해시를 대조하고 기존/새 전체 색인을 먼저 보존한 뒤 현재 색인을 원자적으로 교체한다. 등록부가 생긴 환경은 이전 전체 재생성 명령으로 이 절차를 건너뛸 수 없다.
- 원본과 색인을 삭제하지 않아 과거 보고서의 corpusSha256+chunkId를 그대로 조회한다. 서버는 요청마다 반영된 색인을 확인하며 각 요청의 선택 버전은 유지한다. 과거 버전이 없거나 손상되면 현재 자료로 대체하지 않는다.
- 최초 구현은 허용 공식 호스트의 UTF-8 HTML와 관리자 명령 대상이다. 공개 쓰기 API·문서 업로드 화면·PDF 추출·주기적 자동 수집은 포함하지 않는다. 실제 공식 색인에 합성 문서를 추가하지 않고 격리 검사에서 반영/되돌림을 검증한다.

## ADR-016. 국내 법령·공식 안내와 해외 사례를 구분해 전달한다 (2026-11-15)

- 특정금융정보법 법률 제21857호·시행령 대통령령 제36728호의 2026-10-02 시행 본문을 공식 lsInfoR.do에서 확보하고 STR/CTR/CDD 관련 11조문을 선별한다. KoFIU 개요 2절도 추가하고 원본·버전·시행일·해시·문자 위치를 보존한다.
- 새 색인의 evidencePresentationVersion=1.0과 evidence-kr-v2 Context에서 국내 법령/국내 안내/해외 참고 분류를 검색·원문 조회·보고서에 전달한다. 분류는 출처 메타데이터 기준이며 법률 적용·의미 검증 결과가 아니다.
- 명시한 법령/법률·시행령/조문이 없으면 다른 본문으로 대체하지 않는다. 유효 종료일을 임의로 만들지 않으며 특정 날짜 적용과 은행 내규는 필요한 자료가 없으면 보류한다. 합성 거래의 과거 시각에 수집한 법령이 적용된다고 주장하지 않는다.
- 과거 색인의 evidence-v1 표현·Context·보고서 재현을 유지한다. 기존 평가의 정답/해시를 변경하지 않고 새 자료 연결 확인은 별도 24개 질의로 검사한다. 이를 독립 검색 정확도·법률 정확도 평가로 주장하지 않는다.

## ADR-017. 근거 적합성은 버전 고정 원문과 제한된 확인 조건으로 점검한다 (2026-11-15)

- 룰별 국내 보고/고객확인 일반 근거와 유형 참고 역할을 나눈다. 일반 STR 조문으로 순환 유형 근거를 대신하지 않으며, FinCEN 집금 사례의 현금/지역 맥락과 FINTRAC의 실제 고객 조건을 계좌 수만으로 충족했다고 표시하지 않는다.
- 정확한 청크·원본/본문/발췌 해시와 역할·조건을 불활성 JSON 정책으로 고정한다. 정책은 개발자 검토 초안이며 도메인 검토가 필요하다. 정책을 색인 안에 보존하고 새 기준은 새 색인으로 반영해 과거 보고서/사실 조회를 재현한다.
- 관찰 가능한 구조/지급 방식과 데이터에 없는 동일 자금·고객 관계·경제적 목적·지역을 구분한다. 근거가 없거나 버전이 바뀌면 유사 문서나 보조 검색으로 대체해 충분하다고 표시하지 않는다.
- 검토 보고서는 근거 부족 안내와 정책 인용을 유지해야 한다. 원문 앞부분의 무관한 인용, 근거 충분/제출 가능 표시 조작, 필수 안내 제거는 자체 해시가 맞아도 거부한다. 수치/인용/본문 일치의 valid와 근거 충분/의미/법률 판정은 구분한다.
- 새 Context는 evidence-fit-v3, API는 0.6.0이며 assess_evidence_fit 도구를 추가한다. 항상 사람 검토·제출 불가·의미/법률 판정 미완료를 유지한다. 실제 LLM 호출이나 DB 쓰기는 하지 않는다.

## ADR-018. 새 질문 평가의 코드·자료·정답을 실행 전에 고정한다 (2026-11-15)

- 새 질문 작성 전에 운영 코드/자료 해시를 남기고 새 60문항·정답 대안을 작성한다. 모든 정답 발췌의 존재·요청 범위를 확인하고 기존 평가/코드 질문과 동일/고유사 문장 중복을 검사한다. 동일 개발자가 작성했으므로 외부 독립/전문가 검수 평가로 부르지 않는다.
- 실행 코드·색인·질문을 복사하고 해시를 검증한 복사본으로 한 번 평가한다. 실행 시작 기록과 결과의 덮어쓰기를 막는다. 실제 평가 전 보호 기능 검사는 합성 입력으로 하며 실측 후 코드/정답을 조정하지 않는다.
- 같은 사실의 법령/안내 근거는 정답 대안으로 허용한다. 대표 top3 절/발췌 확보율과 보조 본문 포함 확보율을 분리한다. 미지원 검색 보류와 생성 답변 정확도·법률 적용은 구분한다.
- 첫 결과의 근거 누락 8건과 미지원 관련 본문 노출 6건을 보존한다. 이 질문을 개선에 사용한 다음 측정은 회귀로 구분하고 새 판정용 질문은 별도 확보한다. 기존 48문항 개발 지표와 직접적인 성능 변화율로 비교하지 않는다.

## ADR-019. 요청한 자료 범위를 확인한 뒤 검색하고 보류 이유를 제공한다 (2026-11-15)

- 은행 내부 문서, 지정 발행기관 원문/구간, 관할의 법령, 사례별 고객 값, 자동 결정 요청을 제한된 문구/메타데이터 규칙으로 확인한다. 다른 문서의 본문 언급이나 다른 은행 자료로 요청 원문을 대신하지 않는다. 일반 보고 절차·확인 항목·법률상 절차 마련 의무는 별도로 허용한다.
- 정책 버전 1.0을 색인에 보존하고 검색에 scopeAssessment/보류 이유를 전달한다. Context/보고서/Agent의 answerDisposition으로 원질문 답변 보류를 명시하며 보조 인용·거래 사실을 원질문의 답으로 표시하지 않는다. 일반 의미/답변 가능성을 자동 검증한 것으로 주장하지 않는다.
- 이전 정책의 색인은 인용/사실 조회와 저장 보고서 검증에 유지한다. 새 Context/보고서/적합성 요청에서는 이전 정책 색인을 선택해 현재 조건을 우회하지 못하도록 legacy_corpus_read_only를 반환한다. 관리자의 명시적 정책 변경은 이전/새 색인을 보존한다.
- V4의 6건을 개선 대상으로 사용했으므로 20/20 보류 결과는 회귀로 기록한다. 지원 32/40을 유지하고 원래 60문항/정답/첫 결과/코드 복사본을 변경하지 않는다. 남은 검색 누락 8건과 새 질문 검증은 후속으로 남긴다.
