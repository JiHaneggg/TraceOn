# TraceOn 팀 연동 확인 · 2026-11-23

첫 공동 시연은 **TX-000619283 / 이전 7일 / 2홉** 순환 송금 사례로 잡는다. 현재 선별한 시연 자료에서 최초 조회는 **69거래**다. 조회 결과가 제공한 후보 계좌를 한 번 추가하면 **72거래**가 된다. 읽은 4건 중 3건이 새 거래이고 1건은 기존 거래와 중복이다. 이 사례는 다른 적재 버전과 섞이지 않도록 시연 자료 버전을 맞춘다.

| 흐름 | 팀에서 함께 확인할 결과 | 담당 |
|---|---|---|
| 거래 조회 → 계좌 추가 | 같은 대상·기간·홉에서 고유 거래 69 → 72건. 거래 ID, 송금 방향, 금액·통화·시각 보존. 추가 조회 후 이전 초안 재사용 차단 | 백엔드·DB |
| 확인할 경로 선택 | 그래프의 송금선과 거래 상세가 동일한 `txId`를 가리킴. 추가분과 기존 룰 근거를 화면에서 확인 | 프론트·DB |
| 초안 → 사실·인용 열기 | 현재 그래프에서 초안을 준비하고, 보고서 금액·시간의 원본 거래와 인용 문서 버전을 따라감. 먼저 기존 템플릿으로 계약을 맞춘 뒤 실제 모델 연결을 별도 검사 | 에이전트·RAG |
| 저장 → 다시 열기 | 저장 목록에서 당시 72거래·룰·초안·인용 본문을 복원. 저장 당시 결과와 사람 검토 필요 표시 | 백엔드·프론트 |
| 발표·시연 준비 | 이 거래로 시연 순서를 통일. 500건 조회 일치와 기존 탐지 평가 수치를 각각 설명 | 문서·팀장 |

## 팀이 같은 기준에서 실행하는 방법

공통 기준 커밋의 시연 자료와 코드를 사용한다. [담당 채팅 안내](role-chat-handoffs.md)에 있는 네 작업은 같은 커밋에서 역할별 브랜치로 나눌 수 있다. 검증을 위해서는 별도로 준비한 시연용 CSV·Neo4j·공개 RAG 색인이 필요하다. 시연 자료는 [DB·룰 준비 절차](db-rule-mvp.md)로 만든다. 스크립트는 1,902거래의 공개 그래프 필드를 정렬한 자료 SHA-256을 대조하므로 다른 자료 버전은 바로 알려 준다. 로컬 설정은 [팀 실행 안내](team-handoff.md)를 따른다.

기준 로컬 DB와 RAG를 시작한 뒤 저장소 루트에서 실행한다. 이 명령은 임시 이력 파일에 저장하고, 새 서버를 띄워 DB·RAG 접근 없이 같은 저장본을 복원할 수 있는지 확인한다.

```powershell
./scripts/start-local-services.ps1
python scripts/verify-team-integration.py
```

팀 API를 실행한 뒤에는 실제 로컬 팀 서비스 주소를 `--base-url`로 지정한다. `--stage graph`는 첫 조회, `expand`는 추가 조회까지, `review`는 이전 초안 차단과 새 근거 확인까지, `archive`는 저장본 복원까지 확인한다. 팀 API에서 `archive`를 실행하면 테스트용 분석 이력이 하나 저장되므로 시연 환경에서 실행한다.

```powershell
python scripts/verify-team-integration.py --base-url http://127.0.0.1:8080 --stage graph
python scripts/verify-team-integration.py --base-url http://127.0.0.1:8080 --stage archive
```

2026-11-23 로컬 기준 실행에서 69→72건과 중복 1건, 같은 요청 재시도, 지난 초안 관련 요청 4개의 차단, 거래 사실 2개와 인용 14개, 저장 요청 중복 방지, 재시작 후 당시 근거 복원을 확인했다. Spring은 별도 연동 대상으로 같은 검사를 사용한다.
