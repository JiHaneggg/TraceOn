# 룰·ML 결합에 수취 계좌 특성 추가 · 2026-11-23

새 표본에서 그래프 특성과 이력 확보 여부를 사용한 결합 모델에 **평소 대비 송금 계좌 증가량**을 더했을 때, 세탁 탐지 수는 84건으로 같았고 정상 오탐은 96건에서 91건으로 줄었다. 새 표본의 보정 Recall은 83.80%로 90% 목표에 미달했다.

## 비교 방식

기존 [계좌별 입금 비교](recipient-activity-evaluation.md)에서 최근 24시간 송금 계좌 수와 앞선 5일의 중앙값 차이를 사용했다. 과거 5일을 모두 조회할 수 있고 입금이 있는 날이 3일 이상이면 `historyAvailable=true`다. 이력이 부족할 때 `senderDelta=null`을 유지한다. 모델 입력에서는 숫자 자리를 0으로 채우고 이력 확보 여부를 따로 알려준다. 이력 부족과 실제 증가량 0을 구별할 수 있다.

| 모델 | 입력 특성 |
|---|---|
| 그래프 ML | 최근 24시간의 송금 계좌 수, 입금 건수, 수취 계좌의 출금 건수 |
| 그래프 ML + 이력 여부 | 그래프 특성, 이력 확보 여부 |
| 그래프 ML + 이력 여부·증가량 | 앞선 특성, 평소 대비 송금 계좌 수 증가량 |

Python 표준 라이브러리로 L2 로지스틱 회귀를 구현했다. 샘플 추출 가중치를 클래스 안에서 적용했다. 룰 점수를 0~1로 바꾼 뒤 모델 점수와 50:50으로 결합했다. 모델 점수는 이 실험의 위험 순위에 사용한다. 계좌 ID와 패턴 라벨은 모델 특성에서 제외했다. 대상 거래 시각과 같은 다른 거래 및 미래 거래도 제외했다.

기존 V2 검증 250건을 같은 수취 계좌 또는 패턴 묶음 단위로 5개로 나눴다. 매번 나머지 네 그룹의 특성과 라벨로 학습한 뒤 남겨 둔 그룹을 채점했다. 이 점수로 보정 Recall 90%를 달성하는 경계 중 오탐이 적은 값을 골랐다. 모델 최종 계수는 검증 250건으로 학습하고 경계와 함께 고정했다.

새 평가 250건은 같은 HI-Small 원본의 이후 구간에서 뽑았다. 시연 자료, V2의 두 평가 세트, 직전 입금 비교 평가에 사용한 대상 거래와 알려진 패턴 묶음을 제외했다. 개발과 평가 간 수취 계좌 및 과거 거래 이력은 겹칠 수 있다.

## 결과

| 새 평가 표본 · 검증에서 90% Recall을 목표로 고른 경계 | 세탁 탐지 / 100 | 정상 오탐 / 150 | 보정 Recall | 오탐률 |
|---|---:|---:|---:|---:|
| V2 룰 단독 | 88 | 110 | 87.78% | 73.33% |
| 룰 + 그래프 ML | 85 | 96 | 84.80% | 64.00% |
| 룰 + 그래프 ML + 이력 여부 | 84 | 96 | 83.80% | 64.00% |
| 룰 + 그래프 ML + 이력 여부·증가량 | 84 | 91 | 83.80% | 60.67% |

이력 여부만 추가했을 때 정상 오탐 수는 같고 세탁 탐지가 한 건 줄었다. 증가량을 더한 모델은 이력 여부만 넣은 모델 대비 오탐을 5건 더 줄였고 탐지 건수와 보정 Recall은 같았다. 이력 확보 사례의 정상 오탐은 81→76건이었고, 이력 부족 사례의 오탐은 각각 15건이었다. 새 표본은 정상 129/150건, 세탁 46/100건이 비교 가능한 이력을 보유했다.

검증에서 오탐률 50% 이하를 목표로 따로 고른 경계에서는 증가량 포함 모델이 새 평가에서 정상 오탐 65/150건, 세탁 탐지 77/100건, 보정 Recall 76.84%를 기록했다. 이 두 경계는 현재 특성의 정탐과 오탐 교환 관계를 보여 준다. 목표 미달과 보유 이력 차이를 고려해 증가량은 연구 비교 특성으로 두고, 운영 경계는 추가 평가로 결정한다.

## 재현

V2 동결 입력과 이전 [입금 활동 평가](recipient-activity-evaluation.md)의 결과 파일을 준비한다. 아래 명령을 저장소 루트에서 실행한다. 새 실행은 파일명을 바꿔 이전 결과를 보존한다.

```powershell
python -m unittest discover -s ml-service/tests -q
python scripts/evaluate-recipient-hybrid.py develop --output artifacts/recipient-hybrid-frozen-next.json
python scripts/evaluate-recipient-hybrid.py evaluate --freeze artifacts/recipient-hybrid-frozen-next.json --output artifacts/recipient-hybrid-fresh-next.json
```

이번 기록은 `artifacts/recipient-hybrid-frozen-20261123.json`과 `artifacts/recipient-hybrid-fresh-20261123.json`에 있다. 평가 결과, 데이터, 학습 파라미터는 Git 제외 폴더에 보관한다. `ml-service/recipient_hybrid.py`는 오프라인 평가 모듈이며, 팀 통합은 [담당 채팅 시작 안내](role-chat-handoffs.md)를 따른다.
