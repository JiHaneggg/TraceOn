## 질문·정답 작성 방식

- `rag-service/evaluation_queries_v4.json`: 지원 40·미지원 20개. 단순 제목 검색 외에 자연스러운 바꿔 말하기, STR/CTR 전제 혼동, 미수집 조문·기관·관할·과거/미래 시점·고객정보·혼합 요청을 포함했다.
- 31개 근거 단위를 작성하고, 같은 사실을 뒷받침하는 법령/공식 안내 등 여러 대안을 허용했다. 그중 하나의 적절한 절과 정확한 발췌를 찾으면 해당 단위를 확보한 것으로 본다. 한 본문이 STR/CTR 두 사실을 모두 담으면 두 단위 모두 인정한다.
- 모든 정답 발췌가 고정된 원문에 실제 존재하는지, 요청 필터 안에 정답 대안이 있는지 실행 전에 확인했다. 그 외의 문서가 무관하다고 단정하는 정밀도 평가는 하지 않았다.
- 동결 시 기존 평가 JSON·예시·코드의 검색 질문 169개와 문장을 대조했다. 정규화한 동일 문장과 문자 2-gram Jaccard 0.85 이상의 유사 문장은 없었다. 이는 의미적 독립이나 작성자 독립을 입증하지 않는다.
- 미지원 질문은 현재 색인/자료의 범위를 기준으로 라벨링했다. 법률 원문을 통째로 보관하더라도 검색에 선별하지 않은 조문은 평가에서 미지원이다. 전문적인 정답 적합성 검수는 후속으로 필요하다.

## 코드·자료 고정과 실행

1. 질문 작성 전에 서비스 운영 코드 14개와 현재 색인의 해시를 `pre-question-baseline.json`에 기록했다.
2. 평가기 자체의 보호 기능은 실제 60문항과 별개인 합성 질문으로 검사했다. 이 과정에서 실제 질문 검색을 실행하지 않았다.
3. 실제 질문과 정답을 검증한 뒤 코드 19개(기존 평가 코드 및 새 평가기 포함), 색인, 질문을 평가 폴더에 복사해 해시를 기록했다.
4. 복사된 엔진으로 한 번 실행하고 첫 실행 기록·질문별 검색 결과·실패 목록을 저장했다. 이미 실행을 시작한 폴더나 기존 결과는 덮어쓸 수 없다.
5. 실행 후에도 운영 코드·색인·질문이 고정 기록과 일치하는지 확인했다. 기존 성능 평가와 보고서 파일도 보존했다.

```text
artifacts/rag-evaluation-v4/
  pre-question-baseline.json  질문 작성 전 운영 코드/자료 기록
  manifest.json              실행 전 코드/질문/자료 해시
  corpus.json                8문서·50청크와 적합성 정책 스냅샷
  questions.json             고정한 새 질문·정답 대안
  implementation/            실제 실행한 복사본 코드
  execution.json             첫 실행 시작 기록
  results.json               60문항의 첫 검색 결과·지표·실패 목록
  report.md                  사람이 읽는 평가표
```

당시 실행 명령은 다음과 같다. **현재 폴더는 이미 실행을 완료했으므로 같은 명령을 반복하면 중단된다.**

```powershell
python rag-service/evaluate_frozen.py freeze --index data/rag/index.json --questions rag-service/evaluation_queries_v4.json --run-dir artifacts/rag-evaluation-v4 --baseline artifacts/rag-evaluation-v4/pre-question-baseline.json
python artifacts/rag-evaluation-v4/implementation/rag-service/evaluate_frozen.py run --manifest artifacts/rag-evaluation-v4/manifest.json
```

새 평가 버전은 질문 작성 전에 별도 운영 코드/자료 기록을 만들고 새 폴더에 고정한다. 같은 결과를 재현할 때는 원래 실행 폴더를 보존하고, 별도 폴더에 manifest/corpus/questions/implementation만 복사해 재현 실험으로 구분한다. 추가 모듈·코드·자료·질문의 변경은 검출한다. 해시는 변경 대조용이며 디지털 서명이나 파일시스템 불변성을 인증하는 기능은 아니다.

## 지표의 범위

- 대표 결과는 top3 절이며 각 절마다 보조 본문을 최대 2개까지 제공한다. 대표 본문과 보조 본문 포함 발췌 확보율을 따로 계산했다. 보조 본문은 더 많은 문맥을 사용한다.
- 여기의 Recall은 정답 대안으로 정의한 **필요 근거 단위/절을 검색한 비율**이다. 이상거래 탐지 Recall이나 생성 답변 정확도가 아니다.
- 미지원 검색 보류는 결과가 비어 있고 `no_evidence` 또는 `insufficient_scope`인 경우로 정의했다. 관련 본문을 반환한 사례는 별도로 검토한다. 답변 보류를 명시하면서 참고 문서를 보여주는 전체 Agent 동작은 별도 평가가 필요하다.
- 실제 LLM 호출 0회. 생성 답변의 전제 정정·의미적 뒷받침·환각·법률 적용·최종 STR 판단은 측정하지 않았다.
- 같은 개발자가 작성한 소규모 비무작위 질문이다. 범주별 100%를 전체 금융 질문의 정확도로 일반화하지 않는다. 기존 48개 개발 질문의 수치와도 조건이 달라 직접적인 향상/하락률로 비교하지 않는다.
- 검색 시간은 로컬 검색 함수만 측정했다. DB·네트워크·모델·관제 화면의 전체 응답 속도 지표가 아니다.
