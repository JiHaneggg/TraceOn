# 실제 Neo4j 그래프 시각화 — 2026-11-16

`http://127.0.0.1:8093`에서 시연 거래 선택 → 실제 DB 조회 → 계좌/송금 표시 → 근거 강조 → 원본 상세 확인이 동작한다. 현재는 **로컬 읽기 전용 시연 화면**이다. [그래프→RAG 연결](graph-rag-integration.md)로 원문·거래 사실·검토 초안·재검사·다운로드를 추가했다. Spring 운영 Graph API와 지속적인 분석 이력 저장은 후속이다.

## 실행

Python 3.10 이상과 준비된 로컬 Neo4j/시연 데이터가 필요하다. 화면은 빌드·npm 설치·외부 CDN 없이 실행한다. Docker를 새로 시작하지 않는다.

```powershell
# 이미 DB가 실행 중이면 생략. 기존 로컬 배포 파일이 준비된 환경 기준
.\scripts\start-local-neo4j.ps1
.\scripts\start-graph-viewer.ps1
```

브라우저에서 `http://127.0.0.1:8093`을 연다. 포트 변경은 `-Port 8094`로 지정한다. 서비스 로그와 PID는 `artifacts/graph-viewer/`에 보관한다. 종료할 때는 해당 PID가 이 저장소의 `graph-viewer/server.py` 프로세스인지 확인한 후 종료한다.

## 구현 범위

- 실제 DB에 적재된 시연 거래 **12건**의 목록과 검색/선택. 원본 정답 라벨은 화면·룰 입력에 제공하지 않는다.
- 거래를 선택할 때마다 Neo4j에서 다시 조회한다. 미리 그린 가짜 그래프나 저장 파일로 자동 대체하지 않는다.
- 계좌 노드, 송금 방향 화살표, 개별 거래 ID를 보존한 중복/역방향 송금선, 원본 통화의 금액 표시.
- 대상 거래·룰 근거·주변 거래를 구분하고 근거 중심/전체 연결을 전환한다. 보이는 계좌/거래 수를 별도 표시한다.
- 노드/송금선 클릭 상세, 계좌 이동·확대/축소·맞춤·재정렬, 거래 표 선택·페이지 이동·근거 필터.
- 순환·집금·분산 룰의 근거 ID, 경로 선택 강조, 조회 JSON 다운로드.
- 작은 화면에서는 거래 선택 드롭다운과 세로 배치를 사용한다. 실제 좁은 브라우저에서도 선택·그래프 표시를 확인했다.

금액은 원본 문자열과 Decimal 합산으로 유지한다. 서로 다른 통화를 합치거나 환율을 추정하지 않는다. 계좌 입금 상세는 수취 금액/통화, 출금은 지급 금액/통화를 표시한다. 노드의 계좌번호와 은행 ID를 임의 기업명·실소유자 이름으로 바꾸지 않는다.

초기에는 근거 거래와 대상 거래만 표시한다. 탐지가 없으면 대상 거래만 보이며 정상 확정이 아님을 표시한다. 전체 연결에서 주변 거래를 확인할 수 있다. 룰 점수는 확률이 아니며 ML 점수가 아니다.

## 조회 API

| 경로 | 용도 |
|---|---|
| GET `/api/health` | 실제 DB 연결 확인 |
| GET `/api/cases` | 허용된 12개 거래를 DB에서 조회 |
| GET `/api/graph?txId=TX-000619283&hops=2&windowDays=7` | 공통 graph JSON·기본 룰 결과·highlightTxIds·집계·조회 출처 |

입력은 목록에 있는 거래 ID, 홉 1/2/3, 이전 기간 1/3/7일만 허용한다. 계좌당 최근 50건·최대 1,000거래, 동시 DB 조회 2개, 요청 내 조회 예산 20초·개별 네트워크 대기 최대 8초다. 사용자 Cypher·임의 파일 경로·DB 쓰기 API는 제공하지 않는다.

로컬 접속만 허용하고 비밀번호는 서버에서 `.env`/환경변수로 읽는다. 브라우저에는 DB 주소·인증 헤더·비밀번호·개인 경로를 보내지 않는다. 정적 파일도 지정한 화면 파일만 제공한다. DB 오류는 비밀값을 포함할 수 있는 원본 예외 대신 일반 안내로 반환한다.

## 검증

- Python API 검사 **10개**, JavaScript/실제 Cytoscape 모델 검사 **8개** 통과. 조회/파일/호스트 제한, 쓰기 거부, 오류 비밀값 미노출, Decimal·큰 금액 보존, 통화별 입출금, 송금 방향·병렬 거래·근거 ID 대응을 검사했다.
- 실제 API의 **12사례** 그래프·룰 점수·근거 거래 ID가 관리자 직접 조회/계산과 일치했다. 추가로 1홉/1일·3홉/3일 범위도 대조했다.
- 브라우저에서 순환·집금·미탐지 거래 전환, 전체 연결, 노드 클릭 상세, 조회 범위, 근거 필터, JSON 다운로드를 확인했다. 가로 넘침이 없는 좁은 화면도 확인했다.
- 기존 RAG·룰 구현 파일은 변경하지 않았다. DB 쓰기와 실제 LLM 호출은 0회다. 결과는 `artifacts/graph-viewer/verification.json`에 있다.

```powershell
python -m unittest discover -s graph-viewer/tests -q
node --test graph-viewer/tests/graph.test.mjs graph-viewer/tests/flow.test.mjs
python scripts/verify-graph-viewer.py
```

마지막 명령의 기본 결과는 이미 저장했다. 재검사할 때 `--output`을 새 이름으로 지정한다. 실제 거래 JSON·다운로드·스크린샷·로그는 Git에 올리지 않는다.

## 시연 범위와 후속 연결

DB에는 1,902거래·597계좌의 선별 자료가 있다. 조회 결과는 전체 원장이 아니며 계좌당 상한으로 경로가 잘릴 수 있다. `truncated`와 `sourceGraphComplete=false`를 유지하고 화면에 설명한다. 관계 시각화만으로 동일 자금·거래 목적·정상/범죄 여부를 판정하지 않는다.

이번 Python 조회 연결은 기존 관리자 도구를 고정된 읽기 전용 템플릿으로 제한해 사용한 시연용 연결이다. 운영 아키텍처의 Spring 전용 DB 접근을 대체하지 않는다. 이후 Spring이 같은 그래프/근거 ID 규격을 반환하도록 연결하고, 현재 RAG의 원문·보고서 API를 화면에 추가한다.

[Cytoscape.js](https://js.cytoscape.org/) **3.35.0**을 MIT 라이선스로 사용한다. 공식 npm 배포본 SHA-512를 확인하고 최소 JS와 라이선스를 `static/vendor/`에 포함했다. 버전·파일 SHA-256은 `static/vendor/manifest.json`에 기록했다. 런타임에는 외부 사이트로 데이터를 보내지 않는다.


## 핵심 경로와 시간순 근거 개선 — 2026-11-16

메인 화면은 **하나의 탐지 패턴을 설명하는 핵심 경로**다. 대상 거래를 포함하는 패턴 중 점수가 높은 것을 먼저 선택하며, 나머지 패턴은 버튼으로 전환한다. 기존 조회 범위의 전체 그래프는 `주변 연결`에서 확인한다. 이 전환은 DB 조회·룰 조건·근거 ID를 변경하지 않는다.

- 집금은 실제 수취 계좌, 분산 송금은 실제 송금 계좌를 중심으로 배치한다. 좁은 화면에서는 송금 방향을 유지한 세로 부채꼴 배치를 사용한다.
- 순환은 룰이 반환한 연결 경로를 사용한다. 원본의 두 계좌 왕복 송금을 임의의 네 계좌 순환으로 바꾸지 않는다. 경로 단절·시각 역전·누락/중복 근거가 있으면 표시를 중단한다.
- 계좌 역할 이름은 화면 설명용이다. 실제 기업명이나 실소유자를 뜻하지 않는다. 그래프에는 은행 ID와 축약 계좌를 표시하며 클릭 상세의 전체 계좌 키로 확인한다.
- 시간순 근거 목록의 번호는 송금선 번호와 대응한다. 항목 클릭·이전/다음은 해당 거래와 양 끝 계좌를 강조하고 원본 상세를 갱신한다. 넓은 화면은 그래프 옆, 좁은 화면은 그래프 아래에 배치한다.
- 집금·분산 목록은 원본 시각순이며 동일 시각은 ID순으로 표시한다. 순환은 룰 경로의 연결 순서를 유지한다. 동일 시각의 실제 선후 관계와 동일 자금 여부는 확정하지 않는다. 원본 시각에 임의의 시간대를 붙이지 않는다.
- 금액은 원본 문자열을 보존한다. 합계는 BigInt로 소수 자릿수를 맞춰 계산하며 통화별로 분리한다. 집금은 수취 금액, 분산은 지급 금액을 합산한다. 순환 합계는 중복 이동을 포함하는 거래 합계이며 자금 원금이 아니다.
- 근거가 많은 패턴은 선 번호를 우선 표시한다. 선택 거래의 금액은 표시하며 `전체 금액`으로 모든 금액 표시를 전환한다. 탐지가 없으면 대상 거래 한 건만 보여주고 정상 확정이 아님을 안내한다.

API 변경은 정적 파일 `/flow.mjs` 허용뿐이다. 외부 라이브러리나 외부 서비스 호출은 추가하지 않았다. RAG 보고서·원문 조회 화면 연결은 별도 후속 작업이다.

검증: Python 조회/제한 검사 **11개**, JavaScript 원본 정합성/시간순/배치 검사 **19개** 통과. 실제 DB 시연 사례 **12건**에서 모든 탐지 근거의 거래 ID·시간 순서·통화별 합계·화면 배치의 계좌 동일성을 대조했다. 순환 2건, 집금 1건, 분산 1건, 현재 룰 탐지 없음 8건이다. 이는 UI와 원본의 대응 검사이며 탐지 정확도 평가가 아니다. 대조 결과는 Git에서 제외되는 `artifacts/graph-viewer/flow-verification-v2.json`에 보관한다.
