# TraceOn 진행 상황 · 2026-11-23

팀 공유 기준은 `codex/rag-safe-share`다. Neo4j 그래프, Spring 검토 API, RAG, 웹 화면, 실제 Judge 평가를 각 단계에서 확인했다. 남은 핵심은 Spring과 프론트에서 검토자가 선택한 같은 거래의 Judge 판정과 사유를 확인하고 저장·복원하는 통합 시연이다.

## 구현과 검증

| 영역 | 확인한 결과 | 다음 작업 |
| --- | --- | --- |
| DB·데이터 | 기존 평가 500건을 별도 Neo4j에서 조회해 거래 ID·금액·통화·계좌·시각과 룰 결과를 대조했다. | 시연용 그래프·시점·계좌 확장 결과와 인용 버전을 고정하고 원본과 대조한다. |
| 룰·ML | 도입 목표 Recall 90%로 경계를 잡은 새 250건에서 룰의 보정 Recall 87.78%·미탐 12건, 이력 특성을 포함한 룰+ML 83.80%·미탐 16건을 기록했다. 룰+ML 오탐률은 60.67%, 룰 오탐률은 73.33%다. | 시연 후보 단계는 룰부터 사용한다. 결합 방식의 경계와 오탐·미탐을 추가 검증한다. |
| Spring | 실제 Neo4j 그래프, 룰, RAG 초안·원문, SQLite 저장·복원을 연결했다. 시연 경로에서 69→72거래, 기본 조회 36조건 및 재시작 후 2개 저장본 복원을 검증했다. | 코드 검증을 통과한 초안을 Judge에 보내고 같은 스냅샷으로 결과를 보관한다. |
| 프론트 | 시연 화면에서 거래 선택, 근거 경로 강조, 송금 상세, 추가 조회, 원문·초안 및 저장본 확인이 동작한다. 예시 데이터 검사 47개가 통과했다. | 실제 Spring API로 시연하고 Judge 판정, 근거 ID, 실패·응답 대기 상태를 화면에 연결한다. |
| RAG | 공식·참고 자료 10문서·61청크의 검색, 보류, 버전 고정 원문, 거래 수치·인용 대조를 연결했다. | 검색과 의미 근거에 대한 외부 검수 범위를 넓히고 시연 인용의 원문 버전을 확인한다. |
| 에이전트 | 룰로 선별한 순환·집금·정상 라벨 사례의 실제 Judge 연결 3건을 검증했다. 별도 그래프 3개·검수 9건은 첫 실행 8/9 일치, 반려 3/3, 무점수 1건이었다. 무점수 사례는 동일 입력 단건 재호출에서 통과했다. | 근거 부족 보류와 모델 응답 무점수를 구분해 반환한다. 통합 화면에서 호출 실패·지연, 동일 조회의 사실·청크 연결, 저장본 표시를 함께 검증한다. |

## 다음 통합 순서

1. 백엔드·에이전트가 Judge 응답 필드와 판정 상태를 확정한다. 원본 거래 및 인용 검증이 먼저 실행되고, 계좌 추가로 스냅샷이 바뀌면 이전 Judge 결과를 초기화한다.
2. 프론트가 실제 Spring 응답에서 원문과 판정 사유를 열고, 실행 중·근거 부족·판정 실패를 구분한다. 저장과 다시 열기에서 당시 그래프·초안·판정을 확인한다.
3. DB·RAG와 문서 담당이 같은 자료 버전으로 브라우저 리허설을 한다. 시연 지연을 기록하고 탐지 Recall과 초안 반려 Recall을 발표표에서 각각 표시한다.
