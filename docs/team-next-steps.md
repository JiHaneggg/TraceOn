# 지금까지 한 일과 다섯 담당자의 다음 작업

2026-11-16 기준. 현재는 **실제 Neo4j 조회 → 룰 경로 → RAG 근거 → 자동 검사된 검토 초안**이 이어지는 로컬 시연 단계다. 실제 LLM·ML 점수 결합과 운영 시스템 통합은 아직이다.

## 완료한 것

- **DB·룰:** IBM AML 전처리, 계좌/송금 그래프, 시연 데이터 1,902거래·597계좌 적재, 집금·분산·시간 순서 순환 룰과 평가 기반.
- **RAG:** 공식 자료 10문서·61청크, 중복 완화·한국어 표현 대응·검색 보류·원문/문서 버전 추적·거래 사실/인용 검사.
- **시연 화면:** 의심거래 선택, 패턴별 그래프와 시간순 근거, 룰 이유, 원문/거래 근거 조회, 초안 재검사와 다운로드.
- **검증:** 실제 DB 12사례의 사실44·인용158·첨부파일24개를 대조했다. 60건 정상/결함 초안의 구조적 검증 평가도 만들었다. 일반 의미 판단·법률 적용·최종 STR 승인까지 검증한 것은 아니다.

## 남은 일

1. 현재 계약을 팀의 Spring/프론트/Agent에 통합하고 대표 사례의 시연을 고정한다.
2. 분석 실행·문서/룰/모델 버전·보고서·사람 검토 상태를 영속 저장한다. 현재 메모리 보관은 20분/24건이다.
3. 실제 LLM 흐름·오류 반려·제한된 재시도, 룰/ML 점수 결합과 비교 실험을 연결한다.
4. 팀장·DB/RAG는 새 질문을 멘토/팀원에게 검수받고 검색/보류를 평가한다. DB의 큰 계좌 조회·경로 누락·속도와 룰의 오탐/Recall도 점검한다.
5. 문서·발표·시연 자료를 실제 구현과 측정 범위에 맞춘다. 검색 회귀 결과와 독립 평가를 구분한다.

## 다섯 담당자에게 전달할 말

현재 DB·룰·RAG 기본 기능과 그래프→근거→검토 초안 시연 화면까지 준비했습니다. 기존 API와 시연 코드를 바탕으로 아래 작업을 이어가면 됩니다.

- **백엔드:** Spring에서 DB·룰·RAG API를 연결하고, 분석/보고서/검토 상태 저장과 실행 환경 구성을 부탁드립니다.
- **프론트:** 현재 화면을 팀 프론트에 통합하고, 그래프·원문·보고서·검토 상태와 오류/대기 표시를 연결해 주세요.
- **에이전트:** 준비된 도구로 식별→설명→검증 흐름을 만들고, 실제 LLM·근거 부족 보류·오류 반려·제한된 재시도와 실행 기록을 연결해 주세요.
- **문서:** 설계도·데이터/Agent 흐름·클래스/API 정의·평가 결과·발표/시연 자료·회의록을 실제 구현 기준으로 통합해 주세요.
- **저는 팀장·DB/RAG로서:** 데이터와 근거의 정확성, 검색/보류 평가, DB 성능과 룰 오탐/Recall을 보완하고 일정·범위를 관리하겠습니다.

룰·ML의 점수 생성/결합 담당과 최종 비교 실험 기준은 함께 확정합니다. 자동 검사 통과와 근거 충분/최종 승인은 구분하며, 현재 초안은 LLM을 호출하지 않는 템플릿입니다.

실행은 [팀 공유 안내](team-handoff.md), 화면/API는 [그래프→RAG 연결](graph-rag-integration.md)을 참고합니다. 원본 데이터·문서 색인·실행 산출물·환경변수는 Git에서 제외되어 별도 준비가 필요합니다.
