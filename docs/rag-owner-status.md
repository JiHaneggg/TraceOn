# 팀장·RAG 담당 작업 현황 — 2026-11-15

현재는 **공식 자료 검색 → 거래 사실 검증 → 보고서 준비·검사 → 원문/거래 근거 조회**까지 구현했다. 최신 호출 방법은 [근거 조회·검증 API](rag-evidence-api.md)를 따른다. 검색 중복 제거·새 질문 평가까지 반영했다. [최신 검색 가이드](rag-search-v3.md), [질문별 평가](rag-search-evaluation.md), [보고서 API](rag-v2.md)를 참고한다. 이전 DB·룰 기반과 고정된 성능 평가 결과는 유지했다.

문서 **후보 등록 → 변경 미리보기 → 검색 반영 → 이전 버전 보존** 관리도 추가했다. 실행법은 [문서 등록·갱신 관리](rag-document-management.md)를 따른다. 당시 공식 5문서를 등록부에 연결하며 원래 색인과 보고서를 보존했다.

2단계에서 **국내 법률·시행령·제도 안내 3문서를 추가해 현재 8문서·26절·50청크**다. 국내 법령 원문/공식 안내/해외 참고 사례를 검색·인용·보고서에서 구분한다. 자료 목록·조문 범위·API 응답은 [국내 공식 근거 자료 확대](rag-domestic-sources.md)를 따른다. 관제 화면은 별도 통합 대상이다.

3단계에서는 **룰별 원문 역할·확인 조건·미확인 항목**을 점검해 근거 부족을 Context/보고서에 표시한다. [근거 적합성 점검](rag-evidence-fit.md)의 새 API·Agent 도구·정책 고정 방식을 따른다. 이는 제한된 조건 점검이며 일반 의미 검증이나 법률 적용 판정은 아니다. 정책은 개발자 검토 초안으로 현업 검토가 필요하다.

4단계는 [새 질문 고정 평가 V4](rag-evaluation-v4.md)를 수행했다. 새 60문항을 실행 전에 코드/정답/자료와 함께 고정하고, 지원 질문 근거 확보 32/40·미지원 검색 보류 14/20을 기록했다. 결과를 본 뒤 검색 코드나 정답은 바꾸지 않았다. 같은 개발자가 작성한 질문으로 외부 전문가의 독립 평가·생성 답변 정확도는 아니다.

이후 [요청 범위·검색 보류 보완](rag-abstention.md)에서 미지원 6건을 개발·회귀 대상으로 보완했다. 기존 문항의 검색 보류는 **20/20**, 지원 근거 확보는 **32/40 유지**다. V4의 첫 결과는 그대로 보존했다. API 0.7.0은 보류 이유와 answerDisposition을 제공하며 과거 보고서 검증/사실 조회는 유지한다.

추가 로컬 작업으로 [검색 누락 8건](rag-search-v5.md)을 모두 보완했다. 같은 V4 문항의 지원 근거 확보는 **40/40**, 미지원 보류는 **20/20**이며 독립 평가가 아닌 회귀 결과다. 자동 검사 **233개**, 실제 원문 45개·새 보고서 24건·과거 기본 보고서 48건 검증이 통과했다. 이번 검색 보완분은 현재 공유 코드에 포함한다.

이후 [순환 유형 공식 근거 보강](rag-cycle-sources.md)으로 **10문서·30절·61청크**, CYCLE 해외 참고 2개를 연결했다. 기존 질문 40/40·20/20, 새 보고서 12건·과거 기본 보고서 60건 검증을 유지했다. 자동 검사 239개다. [멘토 검수용 질문 초안 24개](mentor-review-questions.md)는 전부 검수 대기이며 검색 실행 0회다. 은행 내규는 미제공 상태이고 해외 사례의 업종·지역·거래 목적/실소유자 적용은 미확인으로 남긴다.

멘토의 새 가이드를 반영해 [검증 평가 흐름](verifier-evaluation.md)도 구현했다. 검증 API에 범위를 명시한 수치·인용·조문 태그 지표를 추가하고 정상 30·결함 30개를 고정해 첫 실행했다. 구조적 결함 반려 TP30/FP0/TN30/FN0, 통과 초안 수치 520/520·인용 392/392, 평균 로컬 검증 0.7524초다. 의미 판단·LLM-as-a-Judge·재시도 루프는 미측정이다. **현재 자동 검사 251개**이며 이 추가 작업은 현재 공유 코드에 포함한다.

## 검증과 남은 한계

- 공유 스냅샷 당시 자동 테스트 **217개** 통과: 데이터 16·룰 24·RAG 177. 문서 관리 19개·자료 구분 12개·적합성 19개·평가 보호 10개·요청 범위 17개 포함. 이는 일반 검색 정확도의 100%를 의미하지 않는다.
- 기존 5문서 색인의 48개 질문(관련 32·미지원 16)에서 절 Recall@3는 78.1%→95.3%, 검색 결과 중복 비중은 11.8%→0%, 미지원 보류는 13/16→16/16으로 개선됐다. 질문과 초기·중간·최종 결과를 보존했다.
- 관련 32개 중 31개에서 근거를 하나 이상 찾았고, 보조 문맥까지 필요한 근거를 모두 찾은 질문은 30개다. 대표 본문만의 근거 포함률은 89.1%, 보조 본문 포함은 95.3%이며 후자는 더 큰 문맥 예산을 쓴다.
- 같은 절을 반복하던 기존 26개 개발 질문도 확인해 절 Recall@3 97.2%→100%로 개선됐다. 이는 회귀 검사다.
- 새 질문은 반복 개발에 사용한 수작업 개발·회귀 세트다. 독립 최종평가나 모든 금융 질문의 정확도로 일반화하지 않는다. 과거에 놓친 두 질문은 정의/비교 의도에 맞는 적격 절을 우선 확보해 보완했다. 정답표는 바꾸지 않았고 같은 48개 질문의 절 Recall@3는 95.3%→100%다. 이는 개발·회귀 결과다.
- 실제 Neo4j 12사례에서 원문 93건·사실 32건 조회, 전체 보고서 검사와 금액·시간·건수·인용·본문 변조 거부를 확인했다. 과거 문서 버전도 조회했다. 이는 연결 검사이며 전체 탐지 성능·자유 문장의 정확도·UI 완성을 의미하지 않는다.
- 문서 등록부 연결 후 기존 5문서의 동일 자료 재등록·선택 본문 26건·과거 색인의 원문 조회를 확인했다. `artifacts/rag-document-registry-verification.json`과 재시작한 RAG의 12사례 검사 `artifacts/rag-document-evidence-verification.json`에 결과를 보존했다. 새/수정 문서의 반영과 되돌림은 격리된 합성 문서 검사에서 확인하고 실제 공식 색인에는 가짜 자료를 넣지 않았다. 등록/갱신은 현재 UTF-8 HTML·허용된 공식 호스트 대상이며 자동 수집 일정·PDF/내규 업로드 화면은 후속 범위다.
- 2026-11-15 국내 법률/시행령 본문을 확보해 11조문을 추가하고 KoFIU 제도 안내도 추가했다. 새 원문 50청크와 검색/보류 24건을 확인했다. 실제 Neo4j 12사례에서 인용 153건·사실 32건 조회·보고서 검사를 확인했고, 자료 추가 전 보고서 12건도 원래 색인으로 검증했다. 결과는 `artifacts/rag-domestic-*.json`에 보존했다.
- 이전 법령 수집 실패 기록은 유지하고 새 확보 결과를 pending_sources.json에 추가했다. FATF PDF와 은행 내규는 현재 색인에 없으며, 전체 법령의 유효 구간이나 거래별 법률 적용은 확정하지 않는다.
- 적합성 연결 검사에서 실제 12사례 중 룰 탐지 4건은 근거 추가 필요, 미탐지 8건은 정상 확정 없이 표시했다. 룰 결과/점수는 유지했다. 새 보고서 12건·원문 154건 조회·과거 보고서 24건 검증, 근거 충분/제출 가능 표시 조작과 필수 발췌/안내 제거 거부를 확인했다. 결과는 `artifacts/rag-evidence-fit-verification.json`에 있다. `verification.valid`와 근거 충분 상태는 구분한다.
- 새 질문 첫 평가에서 근거 확보 32/40(80%)·미지원 검색 보류 14/20(70%)·중복 0%를 확인했다. STR 바꿔 말하기 6건·한국어 해외 유형 2건의 근거가 누락됐고, 내규/미수집 기관·관할/사례 고객정보/자동 결정·혼합 요청 6건은 관련 본문을 반환했다. `answerability=not_assessed` 상태였으며 실제 답변 생성은 측정하지 않았다. 결과는 `artifacts/rag-evaluation-v4/results.json`, 평가표는 `report.md`에 있다. 이 질문은 이제 회귀 자료로 취급한다.
- 요청 범위 보완 회귀에서 위 미지원 6건이 모두 보류되고 지원 질문별 통과 여부는 유지됐다(32/40). 실제 API/보고서 6건의 보류 사유, 새 거래 보고서 12건, 과거 보고서/사실 조회 36건을 확인했다. 결과는 `artifacts/rag-abstention-verification.json`이다. 원문/순위/점수/원래 정답은 바꾸지 않았고 이후 새 질문 검증이 필요하다.
- 실제 LLM 호출은 API 키·모델 설정이 없어 미실행이다. 기본 보고서의 generation.llmCalled는 false다. 모델이 정해지면 실제 호출·비용·지연·출력 검증을 진행해야 한다.

## 다음 우선순위

1. **적합성 기준 현업 검토·자료 보강:** 구현한 룰별 원문 연결/조건 초안을 멘토와 검토한다. 순환 유형 원문, 고객/소유자 관계·거래 목적·지역 등 누락된 근거와 법령 유효 구간을 보강한다. 은행 내규는 팀/멘토가 사용 가능한 버전을 제공해야 한다.
2. **별도 작성·검수한 새 질문 평가:** 검색 누락 8건은 보완했다. 이제 멘토/팀원이 작성한 새로운 질문과 보류 경계 표현으로 검증한다. V4 첫 결과/정답은 보존하고, 보완에 사용한 질문의 재측정과 새 질문 첫 평가를 구분한다.
3. **실제 LLM 검증:** 서버 환경에 키·모델을 설정한 뒤 openai 모드를 명시해 실제 호출을 확인한다. 현재는 검증된 설명과 ID를 선택·정렬하는 제어 방식이다. 더 자유로운 설명 생성은 별도 의미 검증이 필요하다.
4. **팀 서비스 통합:** Spring Graph API와 룰/ML 결합 결과를 연결하고, contextId·reportId·룰/모델 버전·검토 상태 저장을 백엔드 담당과 맞춘다.
5. **화면 통합:** 프론트가 highlightTxIds로 경로를 강조하고, factId·chunkId에서 거래/원문 근거로 이동하며, 보고서 확인·다운로드를 제공하도록 연결한다.

| 백엔드/DB | Spring의 Neo4j 조회 API·금액/시각/ID·조회 제한·보고서/검토 상태 저장 |
| 룰/ML | 점수·버전·근거 ID·결합 방식·탐지 평가 |
| Agent/LLM | 도구 호출·실제 모델 설정·설명 정책·검토 흐름 |
| 프론트 | 의심 거래 선택·경로 강조·점수/근거/보고서 화면 |

위 전체 MVP 흐름 중 로컬 화면의 `의심거래 선택 → 연결 경로 → 의심 경로 강조 → 룰 점수·RAG 근거 → 검토 초안 확인`을 연결했다. Spring 운영 API·룰/ML 결합·실제 LLM·지속적인 분석/검토 상태 저장은 후속이다. 명령은 저장소 루트 `TraceOn/`에서 실행한다. 최신 공유 브랜치는 `codex/rag-safe-share`다. 개인 경로가 들어 있던 이전 커밋을 포함하지 않도록 `main`의 초기 공개 커밋에서 분기한 코드 스냅샷으로 공유한다. 기존 작업 내용과 팀 실행 방법·데이터 제외 범위는 [공유 안내](team-handoff.md)를 따른다.

1차 기록은 [기본 구현 가이드](rag-mvp.md)와 `artifacts/rag-neo4j-smoke.*`, `artifacts/rag-retrieval-evaluation.json`, 이전 색인 `data/rag/versions/v1-*.json`에 보존했다.

## 2026-11-16 그래프→RAG 화면 연결

[그래프→RAG 연결](graph-rag-integration.md)을 추가했다. 선택 경로에서 공식 자료·저장 원문 위치·수치의 원본 거래를 확인하고, 전체 검증 결과와 근거 부족 상태를 구분한 검토 초안을 연다. 내려받기 전에 원래 보고서를 재검사한다. 거래/범위/경로 변경 시 이전 초안을 지운다.

관련 자동 검사 55개(Python26·JavaScript29), 실제 DB 12사례의 사실44·인용158개 조회와 초안 준비/재검사가 통과했다. 기존 RAG·룰·고정 평가 엔진은 변경하지 않았고 실제 LLM 호출/DB 쓰기는 0회다. 현재 연결은 템플릿 기반 로컬 시연이며 메모리 보관은 20분/24건으로 영속 이력을 대체하지 않는다.

이 단계의 화면 연결은 완료했다. 다음 본인 작업은 분석/검토 이력 저장 계약, DB 평가 조회 경로·성능 점검, 검수한 새 질문의 첫 평가, 공식 자료 갱신 점검이다. 멘토 질문 24개의 검수 대기 상태는 유지한다.
