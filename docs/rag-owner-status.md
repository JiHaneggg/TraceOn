## 검증과 남은 한계

- 자동 테스트 **116개** 통과: 데이터 16·룰 24·RAG 76.
- 새 48개 질문(관련 32·미지원 16)의 절 Recall@3는 78.1%→95.3%, 검색 결과 중복 비중은 11.8%→0%, 미지원 보류는 13/16→16/16으로 개선됐다. 질문과 초기·중간·최종 결과를 보존했다.
- 관련 32개 중 31개에서 근거를 하나 이상 찾았고, 보조 문맥까지 필요한 근거를 모두 찾은 질문은 30개다. 대표 본문만의 근거 포함률은 89.1%, 보조 본문 포함은 95.3%이며 후자는 더 큰 문맥 예산을 쓴다.
- 같은 절을 반복하던 기존 26개 개발 질문도 확인해 절 Recall@3 97.2%→100%로 개선됐다. 이는 회귀 검사다.
- 새 질문은 반복 개발에 사용한 수작업 개발·회귀 세트다. 독립 최종평가나 모든 금융 질문의 정확도로 일반화하지 않는다. 기대한 STR 정의 절을 놓친 두 질문을 평가 상세에 그대로 기록했다.
- 실제 Neo4j 12사례에서 새 대표/보조 인용을 포함한 초안 검증·변조 거부를 확인했다. 이는 연결 검사이며 전체 탐지 성능·자유 문장의 정확도·UI 완성을 의미하지 않는다.
- 법령 원문은 국가법령정보센터 시스템 점검으로 미확보, FATF 원문은 403으로 수집 실패했다. 이를 가짜 원문이나 안내 자료로 대체해 법령이라고 표시하지 않았다.
- 실제 LLM 호출은 API 키·모델 설정이 없어 미실행이다. 기본 보고서의 generation.llmCalled는 false다. 모델이 정해지면 실제 호출·비용·지연·출력 검증을 진행해야 한다.

## 다음 우선순위

1. **법령·내규 확보:** 점검 종료 후 공식 조문·시행일·버전·유효 구간을 확보하고 원문과 대조한다. 은행 내규는 팀/멘토가 사용 가능한 문서 범위를 제공해야 한다. 해외 사례는 한국 의무·기준으로 적용하지 않는다.
2. **검색 품질 후속 검증:** 남은 정의 절 누락과 정답 후보의 완전성을 전문가와 검토한다. 독립된 더 넓은 한국어·미지원·시행일 질문으로 임베딩/재정렬과 문맥 예산·근거 누락·오탐을 비교한다. 개발한 48개 질문을 새 최종평가로 재사용하지 않는다.
3. **실제 LLM 검증:** 서버 환경에 키·모델을 설정한 뒤 openai 모드를 명시해 실제 호출을 확인한다. 현재는 검증된 설명과 ID를 선택·정렬하는 제어 방식이다. 더 자유로운 설명 생성은 별도 의미 검증이 필요하다.
4. **팀 서비스 통합:** Spring Graph API와 룰/ML 결합 결과를 연결하고, contextId·reportId·룰/모델 버전·검토 상태 저장을 백엔드 담당과 맞춘다.
5. **화면 통합:** 프론트가 highlightTxIds로 경로를 강조하고, factId·chunkId에서 거래/원문 근거로 이동하며, 보고서 확인·다운로드를 제공하도록 연결한다.
