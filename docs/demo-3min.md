## 시작 전 준비

- 저장소 루트에서 준비된 로컬 데이터·서비스를 사용한다. 시연 DB는 합성 선별 자료 **1,902거래·597계좌**다. 500건 평가 전용 DB와 바꾸지 않는다.
- `TX-000619283`, **이전 7일·2홉**을 선택한다. 최초 추출은 계좌당 최근 50건·전체 최대 1,000거래다.
- 공통 코드 기준은 `9663073`이다. 추가 조회 후보 **`70:1004286A8`**를 사용할 수 있는지 확인한다. `accountExpansion.datasetSha256`의 관리 마커 해시는 `be9861911d5cda9c450511566c47df517d3e434cb3fd2ed327d6fe54460d379e`다. 공통 연동 검사가 사용하는 공개 그래프 필드 정렬 해시 `d88ae9888527d71134502602d1f3c9ec41fe0ef65323c4829425993f81653f34`는 해시 대상이 달라 값도 다르다. 건수나 자료 버전이 다르면 DB 담당에게 맞춘다.
- 룰·RAG 서비스와 화면을 준비하고 `http://127.0.0.1:8093`을 연다. 2026-11-23 첫 상태 확인에서 8091·8092는 응답했고, 8093·Spring 8080은 응답하지 않았다. 아래 시작 명령은 발표 전 준비 단계에서 실행한다.

```powershell
# 저장소 루트, 설치·시연 데이터·문서 색인이 준비된 PC 기준
.\scripts\start-local-services.ps1

Invoke-RestMethod http://127.0.0.1:8093/api/health

# 본 시연 전, 임시 저장소에서 공통 흐름 대조
python -B scripts/verify-team-integration.py
```

문서 색인과 로컬 DB가 없는 팀 PC는 [팀 공유 안내](team-handoff.md)를 먼저 따른다. 현재 초안 경로는 `template`이며 실제 LLM 호출은 없다.

## 실패 시 처리와 발표 범위

- 69/72건이 다르면 거래·기간·홉과 자료 버전을 확인하고 새 분석으로 시작한다. 다른 DB의 건수와 섞지 않는다.
- RAG/인용 확인 실패 시 초안 포함 저장을 완료로 표시하지 않는다. 그래프·룰만 저장한 항목은 초안이 없다고 설명한다.
- 임시 스냅샷 만료·추가 조회 충돌(409)은 `거래 다시 조회` 후 새 초안을 준비한다. 재조회하면 추가 조회 진행 상태도 새로 시작한다.
- 서비스 장애 때 이미 저장한 항목을 열어 설명할 수 있지만, 화면의 **저장본 보기·현재 자료 미조회** 표시를 유지하고 실시간 조회 시연과 구별한다.
- 이번 작업은 실제 API·저장소 재확인과 기존 화면 코드/자동 검사에 근거한다. 브라우저 조작, 버튼 배치와 180초 리허설은 이번 작업에서 직접 재확인하지 않았다. [담당별 후속 작업](team-implementation-status.md)에서 프론트·문서 담당이 이어간다.

확인된 로컬 흐름을 팀 Spring·프론트와 실제 모델에 연결하는 일은 별도 완료 기준으로 관리한다.
