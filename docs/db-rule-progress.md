# DB·룰 1차 실행 기록 — 2026-11-14

## 데이터와 적재

- 공식 Kaggle의 HI-Small 거래·계좌·패턴 파일을 `data/raw/HI-Small/`에 다운로드했다.
- 전처리 결과: 거래 5,078,345건, 세탁 라벨 5,177건, 계좌 515,088개, 패턴 370개, 패턴 매칭 거래 3,209건. 계좌 정보 누락 0건.
- 원본 전체를 DB에 넣지 않고 CYCLE/FAN-IN 대표 사례와 정상 대조군의 제한된 이웃을 추출했다.
- 독립 Neo4j 5.26.32에 거래 1,902건과 계좌 597개를 적재했다. 같은 파일을 다시 적재해도 거래가 중복되지 않는다.
- 12개 대상 거래의 Neo4j 반환 노드·거래와 원본 메모리 조회 결과를 모두 대조했다. 원본 금액 문자열과 거래 ID가 일치하며 정답 필드는 조회 JSON에 없다.
- Docker는 기존 시작 소켓 오류로 엔진이 올라오지 않았다. 초기화·삭제 없이 작업 폴더 내부 독립 실행본으로 검증했다.

## 첫 평가 결과와 한계

이 표본은 선택된 사례의 기능 검증용이다. 전체 HI-Small 성능을 의미하지 않는다.

| 구분 | TP | FP | FN | TN | Recall | Precision |
|---|---:|---:|---:|---:|---:|---:|
| validation (6건) | 2 | 0 | 0 | 4 | 1.0 | 1.0 |
| test (6건) | 0 | 0 | 2 | 4 | 0.0 | 정의 불가 (탐지 0건) |

validation에서 선택한 설정은 상대 계좌 2개 이상, 1일 창, 최대 4홉, 점수 기준 75다. validation의 양성은 CYCLE 1건·FAN-IN 1건이며 두 건 모두 순환 룰로 점수 90을 받았다. test도 CYCLE 1건·FAN-IN 1건이지만 두 패턴은 약 3~4일에 걸쳐 발생해 1일 룰 창이 필요한 선행 거래를 제외했다. 또한 기준 75는 집금 룰 점수 65를 통과시키지 않는다. 이 설정을 최종 운영 룰로 채택하지 않는다. test 결과를 보고 같은 test에 맞춰 기준을 수정하지 않았다.

DB 조회 그래프에는 해당 정답 패턴의 거래가 모두 포함되어 있었다(validation 2/2·3/3, test 3/3·8/8). 이번 실패는 우선 룰 시간 창·점수 정책과 작은 검증 표본의 한계로 분리해 분석할 수 있다. 다른 사례에서의 그래프 누락 가능성을 일반적으로 배제하는 결과는 아니다.

다음 평가에는 더 넓은 시기의 다양한 유형을 포함한 validation과 새로운 최종 test를 준비해야 한다. 이후 시간 창, 후보 그래프의 포함 범위, 패턴별 임계값을 검증한다. 최초 test 결과는 초기 실패 기록으로 보존한다. ML 결합은 이 기준선과 비교한다.
