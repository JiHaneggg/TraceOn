# 분석 이력 저장과 다시 열기 — 2026-11-18

## 사용 흐름

1. 거래를 조회한 뒤 **분석 이력 → 그래프·룰 저장**을 누른다. 이 경우 초안 없이 현재 그래프·룰을 보관한다.
2. **근거·초안 준비**를 완료한 뒤에는 **그래프·초안 함께 저장**으로 바뀐다. 초안을 재검사하고 인용 본문까지 모아 원자적으로 저장한다. 일부 원문을 확인하지 못하면 초안 포함 저장을 중단한다.
3. 저장 목록의 항목을 선택하면 **저장 당시 결과**를 다시 연다. 서버가 재시작되거나 임시 조회 ID가 만료돼도 목록과 내용은 유지된다.
4. 저장 당시 그래프·근거 경로·거래 표·룰 점수와, 함께 저장한 초안·수치 사실·인용 절 본문을 확인한다. 초안 없는 저장본에는 그 사실을 명시한다.
5. **저장본 내용 검사**와 근거 JSON/초안 다운로드는 보관된 내용의 일치를 검사한다. 현재 DB·규정 재조회나 현재 시점의 적법성·의미적 충분성 검사가 아니다.
6. 새 자료로 조사하려면 **현재 자료로 새 분석**을 선택한다. 저장본 자체에서는 추가 계좌 조회·새 초안 생성·덮어쓰기를 제공하지 않는다.

저장 당시 초안은 당시 선택 경로를 초점으로 표시하며, 보고서 자체는 당시 조회 그래프와 전체 룰 결과를 대상으로 한다. 그래프 표시 패턴을 바꿔도 저장한 초안을 다른 내용으로 바꾸지 않는다. 사람 검토 필수·최종 제출 불가 표시는 유지한다.

## 저장 구조와 범위

- 거래 관계는 기존 **Neo4j 읽기 전용** 조회를 유지한다. 분석 이력만 별도 로컬 **SQLite** 파일 `data/history/analysis.sqlite3`에 기록한다. 외부 서비스와 새로운 패키지 의존성은 추가하지 않았다.
- 그래프의 원본 ID·계좌·시각·금액 문자열·통화, 룰 결과/설정·근거 ID·조회 범위·통계·출처를 그대로 보관한다. 금액을 실수로 바꾸거나 서로 다른 통화를 합치지 않는다.
- 추가 조회의 자료 SHA-256, 계좌별 페이지 이력(선택 계좌·확인/추가/중복 건수·추가 거래 ID)을 함께 보관한다. 새 `accountExpansion.pageHistory`, `datasetSha256` 필드를 사용하며 기본 공통 그래프 추출은 바꾸지 않는다.
- 초안이 있으면 Context·report·저장 직전 검증 결과·선택 경로와 각 인용의 문서/코퍼스/본문 해시·본문·절·인용 위치·당시 원문 대조 결과를 함께 보관한다. 원본 HTML 전체의 사본을 만드는 기능은 아니다.
- 관련 구현 파일의 SHA-256을 기록해 당시 구성 확인을 돕는다. 최신 코드로 다시 룰/검색/초안을 실행한 결과를 과거 저장본에 섞지 않는다.
- 임시 `reviewId`, `reviewSnapshotId`는 저장하지 않는다. 브라우저가 그래프·룰·보고서·저장 경로를 제출하는 방식도 허용하지 않는다. 현재 서버 스냅샷 ID와 해당 초안 ID만 받는다.

SQLite의 `analysis_history` 표는 `id`, `saved_at`, `tx_id`, `has_review`, `capture_sha256`, `sha256`, `body`, `bytes`를 저장한다. `body`는 스키마 버전·이력 ID·저장 시각·분석 묶음의 정규 JSON 바이트다. `capture_sha256`으로 동일 내용 재저장을 합치고 최초 ID·저장 시각을 유지한다. 다른 그래프/초안/구성이면 별도 이력이다. 기존 이력을 자동 삭제하거나 덮어쓰지 않는다.

| 제한 | 기준 |
|---|---|
| 저장 개수 | 최대 100개 |
| 이력 한 개 | 최대 8MB |
| 전체 이력 본문 | 최대 64MB (SQLite 관리 공간 제외) |
| 목록 한 페이지 | 최대 20개, 저장 시각·ID 커서 |
| 함께 보관할 인용 | 최대 32개 |
| 원문 모으기 | 30초 수집 예산, 각 기존 RAG 호출의 20초 네트워크 상한 유지 |
| 동시 이력 작업 | 1개, 겹치면 429 안내 |
| 저장 요청 | 동일 Origin·JSON·2KB·정해진 필드만 허용 |

시간 예산은 호출 사이와 완료 후에 검사한다. 이미 실행 중인 단일 네트워크 요청을 30초 시점에 즉시 취소하는 보장은 아니다. 최종 실제 표본의 저장은 약 0.7~1.1초였다. 이 수치를 운영 SLA로 해석하지 않는다.

처음 쓰는 파일만 전용 표를 만든다. 다른 표가 있는 기존 파일이나 지원하지 않는 구조는 채택/변경하지 않는다. 정상 저장은 SQLite 트랜잭션과 `synchronous=FULL`을 사용한다. 쓰기 실패·용량 초과 시 부분 저장을 만들지 않는다.

## 로컬 API 계약

| 경로 | 입력·동작 |
|---|---|
| POST `/api/history/save` | `{"snapshotId":"<현재 ID>","reviewId":null}` 또는 같은 스냅샷의 초안 ID |
| GET `/api/history` | 첫 목록, `?cursor=<historyId>`로 다음 20개 |
| GET `/api/history/open?historyId=…` | 저장 당시 payload·선택 초안·이력 메타데이터 |
| GET `/api/history/citation?historyId=…&chunkId=…` | 그 초안과 함께 보관한 인용 절 본문/위치 |
| GET `/api/history/fact?historyId=…&factId=…` | 저장 당시 사실과 보관한 원본 거래 |
| GET `/api/history/verify?historyId=…` | 저장 묶음 해시·거래/문서 식별자 연결 검사 |
| GET `/api/history/download?historyId=…&format=json` | 저장 묶음 전체 JSON |
| GET `/api/history/download?historyId=…&format=markdown` | 초안이 있는 저장본의 당시 Markdown + 저장 시각/범위 안내 |

새 ID는 `H-` 뒤 24자리 16진수다. 목록/열기/원문/사실/다운로드는 Neo4j나 RAG 서비스에 접근하지 않는다. 경로·쿼리·새 보고서·검사 결과를 클라이언트가 주입할 수 없고 저장소 파일을 정적 경로로 제공하지 않는다. 만료/추가 조회로 폐기된 실시간 스냅샷은 저장할 수 없다. 다른 스냅샷의 초안을 섞거나, 저장 중 원래 스냅샷이 무효화되면 거부한다.

응답의 `history.integrity.valid`는 저장 묶음 검사이고 `currentSourcesChecked=false`, `humanReviewRequired=true`, `readyForSubmission=false`를 유지한다. 당시 RAG `verification`도 원형으로 보관하되 화면에 **저장 당시 자동 검사 통과 · 현재 자료 미조회**로 구분한다. 보관 사실 조회는 `recomputed=false`다. 현재 규정/원장으로 다시 검증했다고 표시하지 않는다.

## 검증

- Python 65개·JavaScript/Cytoscape 40개, 합계 **105개**의 검사 범위를 통과했다. 저장 지속성·멱등성·페이지 목록·만료/다른 초안 거부·저장 중 원본 무효화·용량·손상·타 저장소 보호·오프라인 근거 조회·기존 그래프/RAG 동작을 확인했다.
- 실제 합성 시연의 순환·집금·현재 룰 탐지 없음 3사례를 그래프만/초안 포함으로 각각 저장해 **6개** 이력을 만들었다. 새 서비스·새 ReviewBridge·새 SQLite 연결에서 6개 모두 같게 복원했다.
- 이때 Neo4j와 RAG 접근을 의도적으로 거부하는 상태에서 **사실 43개·인용 본문 42개·다운로드 9개**를 대조했다. 같은 초안 재저장 3개는 중복 생성하지 않았고, 별도 손상 사본의 열기/검사/다운로드 3개는 409로 거부했다. Neo4j 쓰기·실제 LLM 호출은 0회다. 이력용 SQLite 저장은 의도된 작업이다.
- 실제 브라우저에서 69거래 그래프만 저장, 추가 조회 후 72거래+초안/원문 저장, 두 저장본 다시 열기, 원문·사실 팝업, 저장본 검사·근거 JSON 다운로드를 확인했다. 화면 서버도 실제 재시작한 뒤 이력 2개와 당시 72거래·초안이 유지됨을 확인했다. 가로 넘침은 없었다.
- 기존 룰·RAG 평가 엔진과 공통 추출 파일은 변경하지 않았다. 이는 보관·복원 정확성 검사이며 탐지 성능이나 법률/의미적 판단 평가가 아니다.

검증 파일은 Git 제외 `artifacts/graph-viewer/history-verification-20261118-v3.json`과 실행별 SQLite 파일이다. 최초 실행 결과도 보존한다. 검사 도구 실행 시 새 출력 파일명을 지정한다.

```powershell
python -m unittest discover -s graph-viewer/tests -q
node --test graph-viewer/tests/*.test.mjs
python scripts/verify-analysis-history.py --output artifacts/graph-viewer/history-new-run.json
```

화면은 기존 `scripts/start-graph-viewer.ps1`로 실행한다. 필요한 경우 CLI `--history-db`로 별도 이력 파일을 지정할 수 있으며 브라우저 API에서는 저장 경로를 받지 않는다.

## 공유·후속 경계

`data/history/` 전체를 Git에서 제외한다. 실제 저장본·검증 DB·다운로드·스크린샷·환경변수는 공유 코드에 넣지 않는다. 저장 파일은 **이 PC의 평문 로컬 파일**이며 OS 사용자 권한에 의존한다. SHA-256은 손상/내용 불일치 검사이며 전자서명·악의적 로컬 변조 방지·은행 원장 진위 인증이 아니다.

팀 백엔드는 동일 계약으로 운영 저장소·사용자/역할 접근 제어·감사 로그·보존/삭제 정책·사람 검토 상태를 설계하고 이관한다. 운영 DB의 일관된 스냅샷, 다중 사용자 동시 작업, 암호화/백업/재해 복구는 이 로컬 시연 구현의 완료 범위가 아니다.
