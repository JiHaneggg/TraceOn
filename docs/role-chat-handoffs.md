# TraceOn 담당 채팅 시작 안내

현재 채팅은 **DB·RAG 담당**으로 사용한다. 그래프 조회와 원본 대조, 룰 평가, 검색·보류·인용 검증을 이어 간다. 아래 네 문구를 TraceOn 프로젝트 안에서 해당 역할의 새 채팅 첫 메시지로 사용한다.

각 채팅은 먼저 현재 Git 브랜치와 작업 상태를 읽고, [팀 연동 확인표](team-integration-check.md)의 동일 시연 자료를 쓴다. 역할별 브랜치와 작업 폴더는 팀이 합의한 공통 기준 커밋에서 만든다. 해당 체크아웃에서 `git rev-parse --short HEAD`로 출발 위치를 확인한다. 각 구현은 확인표의 공통 검사로 대조한다.

## 백엔드 채팅 · Spring 조회와 저장

```text
TraceOn 프로젝트의 백엔드 담당이야. backend/의 Spring 코드에서 시작해줘.
먼저 docs/team-integration-check.md, docs/graph-viewer.md, docs/account-expansion.md, docs/analysis-history.md를 읽어.
첫 작업으로 시연 거래를 선택하면 Neo4j에서 읽어서 기존 공통 Graph JSON과 룰 결과를 반환하는 API를 구현해줘.
TX-000619283의 이전 7일·2홉 그래프에서 69거래와 기존 근거 거래 ID가 일치하는지 검증해줘.
기본 조회가 연결된 다음, 동일 그래프의 선택 계좌 추가 조회와 분석 저장·다시 열기 계약을 연결해줘.
DB·RAG 담당이 만든 공통 규격이나 평가 기준에 변경이 필요하면 근거와 요청을 남겨줘.
```

## 프론트 채팅 · 검토 화면

```text
TraceOn 프로젝트의 프론트 담당이야. 기존 graph-viewer 화면과 docs/team-integration-check.md를 먼저 읽어줘.
팀 프론트의 프로젝트 위치를 확인하고, 아직 없다면 독립 프론트 작업 폴더를 사용해줘.
첫 작업으로 시연 거래 선택 → 그래프와 의심 경로 강조 → 송금선 클릭 시 원본 거래 확인을 구현해줘.
백엔드 연동 전에는 기존 API의 확정된 응답 구조로 예시 데이터를 사용하고, 시연 거래의 txId가 표·그래프·근거에서 같은지 확인해줘.
다음으로 계좌 추가 조회 69→72건, 이전 초안 초기화, 인용·원본 확인과 저장본 다시 열기 화면을 연결해줘.
```

## 에이전트 채팅 · 검증 가능한 초안

```text
TraceOn 프로젝트의 에이전트 담당이야. docs/rag-evidence-api.md, docs/graph-rag-integration.md와 rag-service/agent_tools.json을 읽어줘.
첫 작업으로 같은 조회의 그래프·룰 결과에서 식별 → 근거 수집 → 설명 초안 → 검증 결과 반환 흐름을 실행해줘.
처음에는 기존 템플릿과 고정 가능한 테스트 데이터로 세 가지를 확인해줘.
일반 사례는 사실·인용 대조를 통과하고, 근거가 없으면 보류하며, 금액이나 인용을 잘못 넣은 초안은 반려해야 해.
실제 모델을 연결할 때도 점수와 원본 사실은 도구에서 받게 하고, 재시도 횟수와 사람 검토 필요 여부를 보여줘.
```

## 문서 채팅 · 발표와 시연 근거

```text
TraceOn 프로젝트의 문서·발표 담당이야. docs/team-integration-check.md를 기준으로 실제 구현과 평가 근거를 확인해줘.
첫 작업으로 TX-000619283의 조회 → 추가 조회 → 초안 검증 → 분석 저장·다시 열기를 3분 시연 순서로 정리해줘.
아키텍처 한 장, 담당별 현재 상태, 근거가 되는 평가 표도 함께 준비해줘.
500건 Neo4j 조회 대조와 탐지 평가의 의미를 각각 표시하고, 로컬 시연과 팀 연동의 현재 상태를 코드로 확인해줘.
docs/를 작업 위치로 쓰고 다른 담당 변경이 필요한 부분은 해당 채팅에서 이어갈 수 있게 적어줘.
```

공통 시연의 완료 기준은 같은 거래에서 원본 ID를 따라가며 **69→72건 추가 조회, 거래·인용 근거 확인, 검토 초안 저장과 복원**이 이어지는 것이다.
