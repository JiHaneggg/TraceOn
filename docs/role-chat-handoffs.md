현재 채팅은 **DB·RAG 담당**으로 사용한다. 그래프 조회와 원본 대조, 룰 평가, 검색·보류·인용 검증을 이어 간다. 아래 네 문구를 TraceOn 프로젝트 안에서 해당 역할의 새 채팅 첫 메시지로 사용한다.

작업을 DB·RAG, 백엔드, 프론트, 에이전트, 문서·발표로 나눈다. 담당별 작업 전에 현재 Git 브랜치와 변경 상태를 확인한다. 공통 출발점은 공유 브랜치 `codex/rag-safe-share`의 최신 커밋이며, [팀 연동 확인표](team-integration-check.md)의 동일 시연 거래를 사용한다. 동시에 코드를 수정할 때는 공통 커밋에서 역할별 작업 폴더와 브랜치를 만들고 서로의 진행 중 변경을 보존한다.

### Agent Judge 우선 작업 · 1차 멘토링 반영

- **23:43–24:36** DeepEval의 DAG처럼 검증 노드마다 확인할 질문과 결과별 분기를 정한다. 금액·시간·건수·인용은 기존 코드로 대조한다. 통과 후 Judge가 각 핵심 주장을 `supported`, `insufficient`, `contradicted` 중 하나로 분류한다. [DeepEval DAG 문서](https://deepeval.com/docs/metrics-dag)
- **53:06** 에이전트 간 토론과 점수를 언급했다. 먼저 설명 담당과 검증 담당을 분리해 벤치마크 기준을 확보한다. 이후 의심 근거와 정상 거래 가능성을 각각 제시하는 검토를 붙이고, 단일 Judge 대비 효과를 같은 사례로 비교한다.
- **20:27–21:23** 기준을 조정할 데이터와 최종 비교 데이터를 나눈다. 동일 입력을 반복 실행해 판정 일치율과 점수 변동을 기록한다. 정답은 별도 검수 라벨을 쓰고 프롬프트, 모델, 근거 버전과 지연을 남긴다.

| 결과 | 시작 검증 사례 |
| --- | --- |
| `passed` | 원장에 A→B→A 경로가 있고 초안은 경로가 관측됐다고 설명한다. |
| `held` | 경로는 확인되지만 원장에 자금 식별이나 거래 목적 자료가 없다. 초안은 같은 자금이 돌아왔다고 단정한다. |
| `rejected` | 거래별 수치와 인용이 정확해도 초안의 해석이 인용 문서의 전제 조건과 반대다. |

제출 전 검토용 상태이며 최종 판단은 사람이 한다. 수치·인용 불일치는 Judge 호출 전에 반려하고, 모델 응답 실패나 근거 부족은 보류한다. 점수는 항목별 판정으로부터 산출해 사유와 함께 기록한다.

**평가 구분:** 초안 검증은 통과·보류·반려 혼동 행렬, 결함 반려 Recall·F1과 반복 판정 일치율을 측정한다. 거래 탐지는 멘토가 제안한 룰 단독·에이전트 단독·결합을 동일한 보류 데이터에서 비교한다. 현재 TraceOn의 룰+ML 탐지 점수와 Judge의 초안 검증 점수는 별개로 기록한다.
