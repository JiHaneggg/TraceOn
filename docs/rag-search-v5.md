`query_processing.py`는 거래/의심/보고 등 복수의 단서가 함께 있을 때 제한된 검색어를 추가한다. 질문 전체나 평가 ID를 외워서 본문을 지정하지 않는다. `search_intent.py`는 이미 검색 기준을 통과한 본문만 재정렬한다. 보고서에 “보고기관”을 기재하는 질문은 최종 수신 기관 질문과 구분한다.

기존 BM25 점수 기준 1.2·어휘 일치 기준 0.22, 대표 top3 절·절별 보조 본문 최대 2개를 유지했다. 필터·요청 범위 보류를 적용한 뒤 검색하며 은행 내규·FATF 원문·EU 법령·사례별 고객 값·자동 결정 요청을 다른 자료로 대신하지 않는다. 일반 검색에 대한 의미적 답변 가능성을 자동 판정하는 기능은 아니다.

## API와 보고서 호환성

- API 0.7.0의 입력과 기존 필드는 유지한다. 새 표현 연결이 적용된 검색에만 선택 필드 `queryExpansion`을 추가한다. 버전 2.0과 적용한 신호 이름을 확인할 수 있다.
- 원문·인용 ID·해시·본문 위치는 변경하지 않는다. 검색어는 원문이나 인용문으로 사용하지 않는다.
- 이미 표준 용어인 보고서 질문은 불필요하게 확장하지 않으며, 기존 검색 응답의 진단 문구/형태도 유지한다. 과거 기본 보고서 48건의 Context·원문·금액·시각·보고서 검증이 통과했다.
- 검색 방식이 바뀌는 임의의 과거 사용자 질문까지 모두 같은 Context ID를 보장하는 것은 아니다. 저장 보고서는 당시 질문·자료·파이프라인 조건으로 검증해야 한다. 검증이 실패하면 같은 보고서라고 임의 인정하지 않는다.

## 검증

- 자동 검사 **233개 통과**: 데이터 16·룰 24·RAG 193. 추가 16개 검사는 합성 문서로 표현 대응, 보고 대상/기재 항목 구분, 무관한 질문, 관할/자료/시점 필터, 보류 우회 거부, 원문 불변, 보고서 검증, HTTP·Agent 응답 일치를 확인한다.
- 실제 API에서 60문항의 결과가 오프라인 엔진과 일치했다. 검색된 원문 **45개**는 보관된 스냅샷과 대조했다.
- 실제 Neo4j 그래프로 새 거래 보고서 **12건**, 개선된 국내 질문 보고서 **6건**, 보류 보고서 **6건**을 검증했다. 과거 기본 보고서·사실 조회 **48건**도 유지됐다.
- 실제 LLM 호출 **0회**. 금액·시간·건수·인용의 구조적 대조이며 생성 답변의 의미적 타당성·법률 적용·최종 STR 판단은 검증 범위 밖이다.
- 과거 V3 비교에서는 검색 엔진뿐 아니라 당시 `query_processing.py`도 고정했다. `baselines/query_processing_v3_published.py`는 공개 커밋 `e258b7890d1aec6f43cd3a4dc22ade1236830812`의 원본이다. 예전 엔진이 새 동의어를 가져다 쓰지 않도록 평가 실행 시 의존성을 분리했다.

```powershell
python -m unittest discover -s rag-service/tests -q
# 로컬 원문·색인·V4 동결 기록·보완 전 before.json 필요
# 새 --output을 사용하여 기존 기록과 보고서 폴더를 보존
python scripts/verify-search-paraphrases.py --live --output artifacts/rag-search-v5/verification-release.json
python scripts/evaluate-evidence-search.py --output artifacts/rag-search-v5/v3-regression-release.json
```

위 두 결과 경로는 이미 실행했으므로 재실행할 때 다른 이름을 지정한다. `--live`는 기존 RAG API와 DB의 읽기 전용 조회를 사용한다. 원문 다운로드·DB 수정·모델 호출은 수행하지 않는다. 결과와 보고서·원문·색인은 `artifacts/`, `data/`에 보존하며 Git에서 제외한다.
