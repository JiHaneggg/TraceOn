# 멘토 가이드 반영: 제어형 보고서 검증 평가 — 2026-11-15

정상 초안과 결함 주입 초안을 구분해 수치·인용·반려 성능·검증 시간을 측정하는 첫 평가 흐름을 구현했다. 기존 `/v1/rag/reports/verify`와 Agent의 `verify_review_report` 응답에 `integrityMetrics`를 추가했다. 입력과 기존 검증 조건은 유지한다.

## 측정 대상과 기준

| 지표 | 측정 범위 | 기준 |
|---|---|---|
| Numeric Fact Match Rate | 사실 ID 표의 금액·시간·건수·계좌, 제어형 관찰 문장·조회 기간을 원본 Context와 대조 | 통과 초안 100%, 필수 사실표 누락 0 |
| Citation Grounding Precision | Context 청크 ID와 그 본문에 존재하는 정확한 발췌의 비율 | 통과 초안 100% |
| Article Tag Presence | 보고서의 조문·항 태그가 검색 본문/절에 존재하는 비율 | 미존재 태그의 통과 불허 |
| PASS/REJECT 분류 | REJECT 양성의 혼동 행렬·정밀도·재현율·F1 | F1 ≥0.85, 결함 반려 Recall ≥90% |
| First-pass Pass Rate | 혼합 입력 전체와 정상 초안의 첫 통과율을 분리 | 구성 비율과 함께 해석 |
| Latency | Context 재구성·로컬 원문 확인을 포함한 검증 함수 시간 | 각 검증 ≤2초 |
| Retry | 자동 재시도 실행부 없음 | 미측정, 목표 평균 ≤1.5회 |
| 의미 판단 | 자유 설명의 논리 비약·정상 상거래 반론 이해 | 미측정, 실제 모델·현업 정답 필요 |

빈 분모는 100%가 아닌 null이다. 숫자를 누락해 남은 값만 일치하는 경우를 막기 위해 Coverage·누락 ID·중복을 함께 반환한다. 조문 존재와 정확한 발췌는 법률 적용이나 주장의 의미적 뒷받침을 보장하지 않는다. 원문 인용·문서 버전의 숫자를 원장 금액과 무차별 비교하지 않으며 임의 자유 본문 전체의 완전한 감사라고 부르지 않는다.

REJECT 양성 기준: TP=결함 반려, FP=정상 반려, TN=정상 통과, FN=결함 통과. 반려 Precision=TP/(TP+FP), Recall=TP/(TP+FN), F1=2TP/(2TP+FP+FN). 정상 통과 Precision=TN/(TN+FN), 정상 통과 Recall=TN/(TN+FP)다.

## 60건 첫 실행

실제 Neo4j에서 읽은 **12개 시연 그래프**로 정상 초안 30·결함 초안 30개를 만들었다. 같은 그래프가 반복되며 독립 표본 60개가 아니다. 정상 초안은 제어형 템플릿으로 생성했고 정답은 개발자가 정의했다. 실제 LLM 초안이나 현업 검수 정답이 아니다.

결함은 사실표 금액 +1, 관찰 문장 금액 왜곡/근삿값, 시각 +1초, 계좌 변경, 본문 유령 조문, 정상 상거래 가능성을 무시한 범죄 단정으로 각 5건이다. 결함 주입 후 reportId를 다시 계산하므로 단순 해시 불일치 검사만으로 반려할 수 없다. 정답·결함 종류는 검증기에 전달하지 않는다.

| 실측 지표 | 결과 | 해석 |
|---|---:|---|
| 통과 초안 수치 일치율 | **520/520 = 100%** | 정의한 범위, 사실표 누락 없음 |
| 통과 초안 청크·발췌 일치율 | **392/392 = 100%** | 의미적 Grounding 정확도와 구분 |
| 통과 초안 조문 태그 존재율 | **370/370 = 100%** | 유령 태그 미통과 |
| 입력 전체 수치 일치율 | **1,020/1,040 = 98.08%** | 의도적 수치 결함 포함 |
| 입력 전체 조문 태그 존재율 | **740/745 = 99.33%** | 유령 태그 5개 포함, 평균으로 허용하지 않음 |
| 혼동 행렬 | **TP30 / FP0 / TN30 / FN0** | 구조적 계약 결함 기준 |
| 반려 Precision / Recall / F1 | **100% / 100% / 1.0** | 이 결함 세트의 결과 |
| 혼합 입력 / 정상 초안 첫 통과율 | **50% / 100%** | 절반을 결함으로 구성 |
| 평균 / p95 / 최대 검증 시간 | **0.7524 / 0.9274 / 1.2049초** | DB 조회·LLM·UI 제외 |
| 평균 재시도 횟수 | **미측정** | 루프·재생성 호출 없음 |
| 실제 LLM 호출 | **0회** | LLM-as-a-Judge 미측정 |

수치/계좌 결함 20건·유령 조문 5건·단정 문장 5건을 모두 반려했다. 단정 문장은 제어형 보고서와 다르기 때문에 거부한 것으로, 급여/가맹점 정산의 의미를 이해한 결과가 아니다. 해당 반론 메모는 합성 검토 카드이며 원본 DB의 거래 목적 필드가 아니다. PASS는 기술적 무결성 통과이고 STR 제출 승인이 아니다.

## 실행과 기록 보존

prepare에서 코드·원문·색인·그래프·초안·정답을 복사하고 manifest/해시를 고정했다. 복사한 실행기만 평가할 수 있고 실행 시작 후 덮어쓰기를 거부한다. 코드·원문·초안 변경과 코드/원문 추가 파일을 검사한다. 보호 검사는 실제 60건과 다른 합성 자료로 했다.

```powershell
python rag-service/verifier_benchmark.py prepare --run-dir artifacts/verifier-benchmark-v1 --count 60
python artifacts/verifier-benchmark-v1/engine/rag-service/verifier_benchmark.py run --manifest artifacts/verifier-benchmark-v1/manifest.json
```

위 폴더는 이미 실행했다. 재측정은 새 폴더에서 회귀/재현으로 구분하고 첫 기록을 보존한다. 실제 그래프·초안·원문·결과는 artifacts/로 Git 제외한다. 발표용 표는 `artifacts/verifier-benchmark-v1/report.md`, 세부 결과는 `results.json`이다.

## 남은 평가

1. 멘토가 정상 상거래 반론·논리 비약·법률 적용의 정답과 근거를 검수한다. [24개 질문 초안](mentor-review-questions.md)은 별도 검색 검수 자료이며 이 초안 반려 평가와 혼합하지 않는다.
2. 실제 설명 모델의 초안을 모으고 같은 Context를 제공한 검증 모델의 판정과 현업 정답을 비교한다. 모델·프롬프트·자료 버전, 실제 호출·비용·실패를 기록한다. 모델의 판정을 스스로 정답으로 삼지 않는다.
3. 최대 재시도·종료/사람 이관 조건을 구현한 후 평균 재시도·전체 E2E 지연을 측정한다. 현재 미측정 값을 0회나 목표 달성으로 표시하지 않는다.

자동 검사 **251개 통과**(데이터16·룰24·RAG211). 실제 API에서도 정상·금액 변조·유령 조문 초안의 지표와 판정이 일치했다. 로컬 서비스에 반영했으며 현재 공유 코드에 포함한다.
