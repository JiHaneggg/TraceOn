# TraceOn 프론트 · 거래 검토 화면

TraceOn 거래 검토 화면입니다. 기존 `graph-viewer/static` 화면과 Cytoscape 3.35.0을 재사용합니다.

## 실행

Node.js 22 이상이 필요합니다. 저장소 루트에서 다음을 실행해 로컬 Spring API에 연결합니다. Spring은 [백엔드 실행 안내](../docs/backend-spring-integration.md)에 따라 시작합니다.

```powershell
cd frontend
npm start -- --port 4174 --api http://127.0.0.1:8080
```

[검토 화면](http://127.0.0.1:4174)을 엽니다. 별도 예시 모드는 아래의 로컬 예시 생성 후 `npm start`로 실행합니다.

## 시연 순서

1. `시연 처음부터`를 누릅니다. `TX-000619283 / 이전 7일 / 2홉`, **69거래**, 룰 90점, 순환 근거 2건이 표시됩니다.
2. 핵심 경로의 송금선이나 시간순 근거를 클릭합니다. 오른쪽 상세와 표의 선택 거래가 같은 `txId`로 이동합니다. 원본 계좌·송금/수취 금액·통화·시각을 확인합니다.
3. `근거·초안 준비`에서 예시 초안을 엽니다. `수치·거래 근거 → 송금액 → 거래 근거`는 **TX-000619283 / 17169.48 / Euro / 2022-09-01T11:02:00** 원본을 가리킵니다. 화면의 EUR 표기는 원본 Euro 통화의 표시 이름입니다.
4. 후보 계좌 `70:1004286A8`의 `최대 25건 더 조회`를 누릅니다. **4행 확인 / 3건 추가 / 1건 중복 → 72거래**가 됩니다. 새 거래는 파란 점선·`이번 추가` 표기로 구분합니다. 이전 초안·인용 창·다운로드 상태는 초기화됩니다.
5. 새 그래프에서 초안을 다시 준비합니다. `연결 근거·원문`에서 인용 본문·강조 위치·문서 버전·코퍼스 해시를 확인합니다.
6. `그래프·초안 함께 저장` 후 목록의 `72거래` 저장본을 엽니다. 그래프·룰·초안·사실·인용 본문이 복원됩니다. 저장본에서는 추가 조회·초안 생성·덮어쓰기가 비활성화됩니다. `현재 자료로 새 분석`으로 돌아갈 수 있습니다.

화면에 **예시 데이터 · 백엔드 미연결**, **사람 검토 필수**, **저장 당시 결과 · 현재 자료 미조회**를 표시합니다. 예시 데이터는 대표 사례 한 건·7일·2홉만 제공하므로 기간·홉 선택은 고정합니다. 룰 점수는 확률이나 최종 제출 승인 상태가 아닙니다.

## 데이터와 저장

예시 모드의 `fixtures/initial.json`, `fixtures/expanded.json`, `fixtures/provenance.json`은 로컬 시연 자료에서 생성합니다. 시연 거래를 72건까지 펼친 뒤 기존 Python 관제 화면에서 초안을 포함해 저장한 SQLite와 RAG 색인이 필요합니다. 거래·룰·원문 버전과 예시 파일 해시를 확인합니다. 생성된 예시는 각자의 PC에 보관합니다.

고정 API 어댑터는 새 룰·RAG·모델을 실행하지 않습니다. 초안 재검사도 고정된 검증 응답 재현이며, 현재 원장·최신 법령 검증이 아닙니다. 실제 서비스로 연결한 검사는 후속 연동 범위입니다.

시연 중 생성한 저장본은 이 폴더의 `.local/history.json`에 보관합니다. 화면/서버 재시작 뒤에도 남습니다. 저장할 때 그래프·룰·초안·인용을 하나의 묶음으로 저장하고, 같은 내용은 중복 생성하지 않으며, 읽을 때 SHA-256 불일치를 거부합니다. 운영 분석 저장소가 아닙니다. `.local/`과 화면 캡처 `artifacts/`는 Git 제외 대상입니다.

## 백엔드 연결

같은 기존 API 계약을 제공하는 서버를 명시적으로 연결합니다.

```powershell
npm start -- --port 4174 --api http://127.0.0.1:8080
```

브라우저는 같은 Origin의 `/api/...`를 사용하고 프론트 개발 서버가 지정한 API로 전달합니다. API 모드에서는 예시 데이터로 자동 전환하지 않습니다. 서버 오류를 그대로 오류 상태로 표시합니다. 이 프록시는 로컬 개발용이며 운영 인증·권한 설계는 팀 백엔드에서 정해야 합니다. 상세는 [연동 안내](docs/frontend-integration.md)를 참고하세요.

## 검증

예시 모드까지 검사하려면 먼저 `frontend` 폴더에서 예시를 생성합니다. 입력으로 필요한 아카이브와 색인은 [로컬 시연 대본](../docs/demo-3min.md)을 참고하세요.

```powershell
python scripts/export-fixtures.py --source ..
npm test
```

기존 그래프/룰 표시·추가 조회·초안·저장본 검사 40개와 신규 시연/API 검사 7개, **47개 통과**. HTTP 검사는 로컬 루프백 연결 권한이 필요합니다.

검사에는 거래 방향/병렬 송금/금액 정밀도, 표·그래프·근거·사실의 ID 일치, 69→72와 중복 병합, 이전 초안의 사실·인용·재검사·다운로드 차단, 저장 후 서비스 재생성과 복원, 모든 보관 인용의 본문 위치, 손상 저장본 거부, API 프록시와 오류 시 예시 대체 금지를 포함합니다. 브라우저 점검 기록은 [화면 검증](docs/frontend-verification.md)에 있습니다.

예시 생성기는 기존 아카이브를 읽기 전용으로 열고 프론트 예시 파일을 만듭니다. API 모드와 생성된 예시의 재생에는 Node.js를 사용합니다.
